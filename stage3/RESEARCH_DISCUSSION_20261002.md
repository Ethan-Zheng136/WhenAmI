# Stage3：是否扩大训练，以及下一步应验证什么

2026-10-02。**讨论稿；本轮没有启动训练，没有修改架构或Stage1/2权重。**
结论：不直接扩大当前R+K；先做一次有判别力的读出适应实验，再决定时间任务改造。

## 1. 文献核对，不只是复述摘要

已读原文与范围：

1. **WoG, World Guidance: World Modeling in Condition Space for Action Generation**
   （arXiv:2602.22010，本地归档PDF）：§3.2、§3.3、§5.3、附录A/B。
   Stage II冻结Future目标编码器，但未来预测监督作用到可训练VLM；
   DiT只读当前z，不直接读取预测Future条件。§5.3/Table8比较了去掉condition
   co-training的变体。论文与本地参考代码在这个关键结构上吻合。
   不能把我们“冻结VLM和DiT、只训外部R/K”的结果当作相同训练方法的复现。

2. **FLARE: Robot Learning with Implicit World Modeling**
   （arXiv:2505.15659v1）：§3.1/§3.2。
   在动作DiT内部加入future tokens，从中间层对齐future embedding；
   action/future流在自注意力内交互。其后训练策略编码器与DiT可适应，
   目标embedding使用EMA更新（不是整个过程永远固定目标）。
   启示：预测任务应该塑造实际决策表示，而不只是外部条件翻译。
   边界：仅增加future tokens或未来对齐loss，不足以构成WhenAmI独立贡献。

3. **Temporal Cycle-Consistency Learning**（CVPR 2019）：
   原始CVF论文，导论/§3。通过同类动作视频之间的时序对应和cycle-back
   学习细粒度阶段表示。不是对潜变量随意做R_inverse(R(x))=x。
   启示：WhenAmI的“何时”应有真实时间位置/阶段的可检验对应关系。
   不能直接假定所有OXE指令共享单调、同速、无回退的进程。

4. **V-JEPA 2: Self-Supervised Video Models Enable Understanding,
   Prediction and Planning**（arXiv:2506.09985v1）：§3.1。
   action-conditioned predictor结合teacher forcing与两步真实时间rollout，
   将预测状态再作为后续输入。冻结视觉编码器不等于冻结整个可学习动力学模型。
   启示：这种多步监督与我们试过的4个Euler去噪区间不同，不能用后者的负结果
   否定前者，也不能据此保证多时间监督会改善本项目。

补充只读摘要/导论：**DAWN**（本地arXiv:2605.11550 PDF），讨论world/action
假设递归交互，任务是自动驾驶；不当作操控性能证据，也不将该文概念直接迁移
成我们的完整解决方案。其余本地邻近文献仅浏览，尚未完成新颖性全面审计。

## 2. 对前面结论的校准

目前可靠描述是：
在固定缓存、813训练窗口、211已观察验证窗口、一个训练种子和一个采样种子、
冻结两个大端点及固定Past动作读出的设定下，没有稳定的Future/回溯增量收益。

不能从中推出：
- Future本身没有信息；
- 所有双向时间推理无效；
- 只要继续堆训练量就会改善；
- 普通K适配器的6%/10%离线误差改善已等同于闭环成功率提升。

冻结有利于控制变量和保护基础模型，但也限制了读出适应额外证据。
这只是待检验解释，不是已经查明的失败原因。

## 3. 下一步先做判别实验，不再同时改五个东西

新的独立试验，原Stage1/2文件绝不修改；这是对此前“端点全冻结”约定的
实验性放宽，不能仍称所有策略接口完全固定。

第一轮优先只让Past DiT具备相同的小型可训练适配器（位置/参数量事前固定）：

| | 原冻结Past读出 | 带相同小适配器的Past读出 |
|---|---|---|
| 无逐样本Future/固定均值 | 基础对照 | 纯适应收益对照 |
| 真实Future oracle | 已有诊断路径 | 额外证据能否被适应后的读出利用 |

两列之间不是等参数实验；**每列内部的有/无Future必须同参数、同预算**。
先用真实Future隔离掉R预测误差；这仍是oracle诊断，不是可部署模型。
如观察到收益，再用新的锁定数据和种子验证，而不是立即引入R来蒸馏。

数据：不再只围绕原211验证窗口调试。新建更大训练子集，保留新的episode级
开发集/最终测试集；开发期只看开发集，锁定方案后再用最终测试集。
它们仍可能被端点预训练见过，必须如实区分“R/适配器未见”和“全模型未见”。
至少多个训练种子；动作块、首动作、gripper一起报告，能闭环时再做闭环。

解释：
- 若适应后的oracle稳定胜同预算无Future控制：先前固定读出可能是限制之一。
- 若仍不胜：不继续无限解冻，转向未来目标、时间锚点、采样和任务定义。
- 若有/无Future同样改善：仍然只是普通微调收益，不能包装为WhenAmI机制。

## 4. 真正向WhenAmI推进的方向（候选，尚未实施）

不把“未来条件预测”本身当终点，而让在线表示描述轨迹中的当下位置。
先只用2—3个明确时间锚点，不恢复复杂长链、高斯精度融合、多轮循环。

```text
训练轨迹：  t-delta -------- t -------- t+delta
               |            |             |
             观测证据      观测证据      观测证据
               \            |            /
                共享的可训练时间表示模块
                    |       |       |
                 s[t-d]    s[t]    s[t+d]
                    |       |       |
                同一个可适应的动作读出
                    |       |       |
               各锚点各自对应的真实动作窗口

在线分支：每个锚点只允许看到该锚点及之前的观测；
训练期后视证据：用于监督/教师，不暗中进入在线分支。
```

需要明确：
- 两个节点的真实delta、动作窗口、输入可见性；16个query不冒充时间节点。
- 时间位置不等于episode百分比，更不一定是全局单调进度；允许停顿/回退。
- 对应关系/局部时间顺序与动作监督结合，不只用无锚点cycle防止恒等解。
- 真值未来动作只可作标签或显式特权训练信息；若预测器条件化于动作，
  必须区分已执行历史动作与部署时自身候选未来动作，不能偷用专家未来。
- 预测/回溯两条路最好在“同一个时刻的解释”处相遇，而不是强迫两个
  独立训练的条件坐标系互相做数值回归。

这比现有R/K更接近研究目标，但只是值得检验的方向，仍需普通适配器、
无Future监督、同参数/预算等控制，以及独立测试证据。

## 5. 资源决策

- 暂不提交320/640卡主训练。
- 先有界验证一个关键假设；不是拒绝训练，而是让每次训练能排除一个解释。
- 新设计锁定后再准备扩大训练与闭环评测，避免把小缓存调参当作研究进展。
