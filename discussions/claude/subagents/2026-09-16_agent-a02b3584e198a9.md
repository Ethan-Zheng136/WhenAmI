 Abstract:Latent actions provide a compact interface between action-free video and downstream decision-making, yet existing Latent Action Models (LAMs) force every transition through a fixed-capacity bottleneck. def _compute_power_biased_weights(sample_horizon: int, power: float, device_str: str) -> torch.Tensor:
    """Compute power-biased weights: P(k) = k^power / sum(1^power..N^power)
    
    Higher power gives stronger bias toward full tokens:
    - power=1.0 (linear): ~40% for full tokens when N=4
    - power=2.0 (quadratic): ~53% for full tokens when N=4
    - power=3.0 (cubic): ~70% for full tokens when N=4

    Returns:
        Weights tensor on the specified device
    """
    weights = torch.arange(1, sample_horizon + 1, dtype=torch.float32, device=device_str) ** power
    weights = weights / weights.sum()
    return weights

    @staticmethod
    def forward(ctx, input, running_ema):
        ctx.save_for_backward(input, running_ema)

# GRAFT POINT 1 调研结果：替换 QFormer 的 16-query 固定瓶颈

## 0. 先说一个我在读代码时发现的、会改变你实现策略的事实（VERIFIED，非论文）

我 clone 了 `github.com/Selen-Suyue/WoG`，读了 `/tmp/WoG/vla/qformer.py`。QFormer 是 `BertModel(BertConfig(..., add_cross_attention=True, is_decoder=True))`，query 通过 `inputs_embeds=query_embeds` 喂入。我又读了本机 `transformers 4.57.0` 的 `modeling_bert.py:958` 和 `modeling_utils.py:1636`，并实测 `_prepare_4d_causal_attention_mask_for_sdpa(ones(1,8),(1,8),...)` 返回 `None`（即 SDPA 走 `is_causal=True`）：

> **`is_decoder=True` 使这 16 个 query 之间的 self-attention 已经是因果掩码的（左到右）。** query i 只能看到 query ≤ i。

这个发现价值很大：OAT 论文（下面 #2）明确说"causal attention over registers"是它 ordering 的两大机制之一，而**你已经免费拥有了一半**。你只缺 nested dropout。所以下面 #1/#2 的移植成本比通常估计还要低，且 ordering 更容易长出来。同时它也解释了你的诊断：单 token probe R²=0.62 而 16 token 只有 0.645——因果结构下 query 0 已经被迫做了"全局摘要"，后 15 个只在补残差，而没有任何损失压力去让它们补有用的残差，于是它们变成噪声，effective rank 卡在 18。

### #3 MQT (Matryoshka Query Transformer) — **唯一一个直接在 learned-query resampler 上做过、且量化了"最少要几个 query"的工作**
- arXiv **2405.19315** | https://arxiv.org/abs/2405.19315 | 提交 2024-05-29（v2 2024-06-07）| Comments：**"Preprint. Our code and model are publicly available at this https URL"**

### #4 AdaSlot: Adaptive Slot Attention — **真正的"自适应个数"，而非"可调个数"**
- arXiv **2406.09196** | https://arxiv.org/abs/2406.09196 | 提交 2024-06-13 | Comments：**"CVPR 2024"**
- 代码：**已确认** https://github.com/amazon-science/AdaSlot （77 stars，官方实现，2024-08 开源，含预训练 ckpt）。注意 `github.com/kfan21/AdaSlot` 是空壳（README 只有一行标题），`kfan21.github.io/AdaSlot/` 是项目页。
- 机制一句话（我从 arXiv HTML 全文精读）：先生成 `K_max` 个 slot，用每 slot 一个**两层 MLP** 输出 keep 概率 `π_i`，用 **Gumbel-Softmax + straight-through** 得到硬 0/1 mask `Z = GumbelSoftmax(π)_{:,1}`（mean-field 分解，把"不定 k 的子集选择"化为一串 top-1 选择），目标是 `E_Z[L_recon] + λ·L_reg(π)`，`L_reg` = 保留 slot 数的期望；再用 **masked slot decoder** 在解码时压制未选中的 slot。论文超参：`λ=0.1`（MOVi）/`0.5`（COCO），`K_max` = 11/24/33。
- **这是四个候选里唯一给出"每个样本各自需要几个 token"的机制**——nested dropout 家族只给"全局有序"，budget 还是推理时人为选。
- 移植进 WoG：
  1. `qformer.py` 加 `self.gate_mlp = nn.Sequential(nn.Linear(32,64), nn.GELU(), nn.Linear(64,2))`，作用在 `v_proj` 输出的每个 query 上；
  2. `Z = F.gumbel_softmax(logits, tau=1.0, hard=True)[..., 1]`，`query_output = Z.unsqueeze(-1)*query_output + (1-Z.unsqueeze(-1))*self.null_token`；
  3. `vla/vla.py:192` 的 loss 改为 `loss = act_loss + 0.3*obs_loss + lam * Z.sum(dim=1).mean()`；`lam` 需扫（从 0.01 起，你的 O^c 只有 32 维/token，正则尺度与图像重建差很多）。
  4. **必须显式加一个 loss 项**（这是它与 #1/#2 的本质差别），必须重训 Stage I。
- 改动量：**~40 行 + 一个新 loss 项**（比 #1 略大，主要是 λ 调参成本）。
- 诊断预测：
  - **能直接把"最小充分容量"变成模型自己报的数字**（`E[Z.sum()]`），比扫 `eval_keep_k` 更有说服力，且可按数据集分层（fractal vs bridge）。
  - 对 rank-18：**能修，但机制不同**——它是"砍掉整个 token"，你的冗余是"跨 token 线性相关"，AdaSlot 会把相关 token 直接关掉，rank 应该逼近实际保留数。
  - **诚实的负面**：Gumbel 门在 Stage II 是麻烦。Stage II qformer 已 frozen+detach，门是确定的（eval 模式），但 oformer 要预测一个**部分被 null 替换的目标**，`obs_loss` 的 cosine 在 null 维上是常数——会稀释梯度。需要把 `obs_loss` 改成只在 `Z=1` 的位置上算（再 ~5 行）。另外 CVPR'24 的实验全在无监督物体发现上，λ 的迁移性未知，**这是四个里调参风险最高的**。
  - QASA（**2601.12936**，提交 2026-01-19，Comments **(none)**）是 K-adaptive 的 2026 改进版，指出"把 slot-count penalty 直接加到重建目标上会造成目标冲突"——恰是我上面担心的问题——它解耦了 slot selection 与 reconstruction。但我**未找到 QASA 的公开代码**（abs 页无任何 github/项目页链接），故只作为"若 AdaSlot 的 λ 调不出来就读这篇"的备选，不列为主候选。

### #5 BC-IB: 用互信息正则显式压掉冗余（信息瓶颈路线）
- arXiv **2502.02853** | https://arxiv.org/abs/2502.02853 | 提交 2025-02-05（v5 2025-05-13）| Comments：**"Accepted by ICML 2025"**
- 代码：**已确认** https://github.com/baishuanghao/BC-IB （HTTP 200，含 `train_libero.py` / `train_cortex.py` / `libero_exp/utils/mine_utils.py`）。我读了 `mine_utils.py`：是标准 **MINE**（`Mine` 类，`loss_type ∈ {mine, fdiv, mine_biased}`，EMA 稳定的 `logsumexp` 项，`get_mi()` 直接返回 MI 估计）。
- 机制一句话：把 IB 原理引入 behavior cloning——最大化 `I(latent; action)` 同时最小化 `I(latent; observation)`，用 MINE 估计两项，加到 BC 目标上；论文自称是"第一个系统研究 BC latent 冗余"的工作。
- 与你诊断的对应关系最直接：你测到 **83% 的 O^c 方差可由"仅当前帧版本 O^c"线性重建**，且 O^c 的因果效应 96–108% 来自 future-only 成分。这正是 `I(O^c; O_t)` 过高、`I(O^c; future|O_t)` 过低。
- 移植进 WoG：
  1. 新增一个小 critic（2 层 MLP，输入 `concat(flatten(O^c), flatten(x))`），直接抄 `mine_utils.py`（~80 行，可整文件 copy）。
  2. `vla/vla.py` 的 loss 加两项：`+ β·MI_hat(O^c; current_frame_feature) − γ·MI_hat(O^c; future_residual)`。current-frame feature 你已经有（`base_pv` 那条路），future residual 需要你在诊断脚本里已经算过的那个量。
  3. 必须重训 Stage I，且要交替优化 critic（额外训练循环）。
- 改动量：**新增一个模块 + 交替优化循环，~150 行**，是这批候选里最贵的。
- 诊断预测：
  - **它治的是"O^c 里装了什么"，不是"O^c 该有多大"**。它会把 83% 的当前帧泄漏压下去，让 O^c 更纯粹地是 future-only——这可能反而让你 Stage II 的 z→O^c 更难（因为 z 本来就更像当前帧摘要）。**这是个真实的方向性冲突，我不认为它是你 GRAFT POINT 1 的答案。**
  - 但它是 **GRAFT POINT 的邻居问题**的好答案：如果你后续想做"为什么真 z 下 O^c 的因果影响比随机 z 低 36%"，这套 MINE 工具是现成的测量器（`get_mi()`），**建议只借它的 critic 当诊断工具，不改 loss**。这样成本降到 ~30 行且不用重训。
- 同族但**无代码**的一篇（供参考，不推荐落地）：**2508.08743** "Boosting Action-Information via a Variational Bottleneck on Unlabelled Robot Videos"，提交 2025-08-12，Comments **(none)**，abs 页无任何代码链接（**UNVERIFIED / 未找到代码**）。它用 VIB 显式最大化 `I(latent action; true action)`，理论分析在，但对你没有可抄的实现。

### #6 FlexTok / ReTok — 只在你发现 nested dropout "把信息过度堆在前几个 token"时才需要
- **FlexTok**：arXiv **2502.13967** | https://arxiv.org/abs/2502.13967 | 提交 2025-02-19（v2 2025-06-04）| Comments：**"ICML 2025. Project page at this https URL"**（即 flextok.epfl.ch）| 代码 **已确认** https://github.com/apple/ml-flextok（重定向到 `apple-aiml-research/ml-flextok`，333 stars）。**OAT 的 `token_dropout.py` 文件头明确写着改编自 EPFL & Apple**，即 FlexTok 就是 OAT nested-dropout 的上游实现——所以你抄 OAT 等于间接抄了 FlexTok。
- **ReTok**：arXiv **2601.01535** | https://arxiv.org/abs/2601.01535 | 提交 2026-01-04 | Comments：**(none)** | 代码 https://github.com/zfu006/ReTok（HTTP 200，5 stars，有 `tokenizer/`、`autoregressive/`、`configs/`，2026-02 有 push——**代码存在但社区验证很弱**）
- ReTok 的机制一句话，以及它为什么可能对你重要：它指出 nested dropout 的**尾截断本质上把信息过度集中在早期 token，token 数增加时下游收益反而受限**；对策是 **Redundant Token Padding**（让尾 token 被激活得更频繁）+ **Hierarchical Semantic Regularization**（把早期 token 的解码特征对齐到预训练视觉基础模型，正则强度向尾部递减）。
- 为什么对 WoG 特别相关：**你已经有一个冻结的 DINOv2**。ReTok 的 hierarchical semantic regularization 正好可以用你现成的 DINOv2 特征当对齐目标，零额外依赖、零额外标注。
- 移植：只在 #1 落地后、如果你观察到"k>8 时 act_loss 不再下降但 k=16 的 O^c 仍然低 rank"（即信息过度前置）时才做。改动 **~60 行**（一个额外的 cosine 对齐 loss，权重按 token index 线性衰减），重训 Stage I。
- 诚实评价：这是二阶修补。**不要一开始就做。**

## 我的落地建议（最省力路径）

**第一步（1 天，~30 行，重训 Stage I 一次）**：抄 OAT 的 `MaskedNestedDropout` 到 `vla/qformer.py`，放在 `v_proj` 之后，`size_sampling_mode="uniform"`，不加任何新 loss。你已经免费拥有 causal query attention（§0），所以 OAT 的两个 ordering 机制你会同时具备。训完扫 `eval_keep_k = 1,2,4,6,8,12,16`，画 act_loss / probe R² / effective rank 三条曲线。**膝点就是你要的最小充分容量**，我预测在 4–8。这一步同时给你 FlexLAM 式的"同 budget 下更优接口"论证。

**第二步（若第一步的曲线在 k>8 后仍平坦但 rank 没涨）**：加 AdaSlot 的 Gumbel 门 + `λ·E[Z.sum()]`，让模型自己报每样本的 k，并按 fractal/bridge 分层看分布。记得同步把 `obs_loss` 改成只在 `Z=1` 位置上算。

**不建议现在做**：BC-IB 的 MINE loss（方向与你 Stage II 的目标冲突，且最贵）——但**强烈建议**把它的 `mine_utils.py` 当纯诊断工具用，去量化你已经观察到的"83% 当前帧泄漏"和"真 z 下因果影响低 36%"。ReTok 留作二阶修补。
