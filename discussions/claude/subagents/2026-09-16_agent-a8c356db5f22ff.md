# GRAFT POINT 6：Future Encoder 的未来帧采样策略

## 0. 先说三个我在源码里实测出的事实（比论文更重要）

我 clone 了 `github.com/Selen-Suyue/WoG` 并读了实际代码。有三个发现直接改变这个 graft point 的优先级：

### 事实 A：QFormer 的 KV 侧**完全没有任何位置/时间编码** — 5 帧是一个无序集合

`vla/qformer.py` 把 `visual_src`（DINO patch）+ `vae_latent` 直接作为 `BertModel(encoder_hidden_states=...)`。我查了本机 `transformers 4.57.0` 的 `modeling_bert.py`（`/usr/local/lib/python3.12/site-packages/transformers/models/bert/modeling_bert.py`，L127-147 `BertEmbeddings`、L568-585 `BertLayer.forward`）：`BertEmbeddings` 只作用于 `inputs_embeds`（也就是 16 个 query），`encoder_hidden_states` 是**原样送进 cross-attention 的 K/V，不加任何 position embedding**。

**推论**：当前的 288 个 KV token（256 DINO = 4 帧 × 8×8，加 32 个 VAE token）对 QFormer 而言是**排列不变的集合**。O^c 在数学上无法区分「t+4 的帧」和「t+16 的帧」——它只能看到「这些帧的并集里出现过什么」。

这对用户的诊断是一个直接的机制解释：**O^c 结构上就无法编码时间顺序，只能编码"未来 Ta 步内出现的视觉内容的集合"**。而在一个 16 步（约 1.6 秒）的窗口里，这个集合和当前帧的集合高度重叠 → **83% 可由 current-frame-only 版本线性重构，这是架构的必然结果，不是训练不足**。同时也解释了 effective rank 只有 18 和 16 query 高度冗余（R²=0.62 单 token vs 0.645 全部）：既然没有时间轴可以分工，16 个 query 就退化成对同一个"视觉内容集合"的重复池化。

> **这是本 graft point 最重要的结论：不加时间嵌入的情况下，改采样点位只能改变"集合内容"，不能创造时间结构。想真正打掉 83%，必须 (a) 加时间嵌入 + (b) 改采样。单做 (a) 或单做 (b) 效果都会被打折。** 好消息是 (a) 只要 ~10 行。

### 事实 B：末尾塌缩 bug 比描述的更严重，而且 pad_mask **算错了 + 被丢掉了**

`prismatic/vla/datasets/rlds/traj_transforms.py` L49-61：


1. **pad_mask 判据用的是 `>= 0`**，这只能检测**轨迹开头**的越界（`window_size=1` 时永远不会发生），**完全检测不到轨迹末尾的越界**（正确判据应该是 `unfloored <= goal_timestep`）。所以 pad_mask 在 WoG 的配置下**恒为全 True**。

3. `datasets.py` 只把 index `[1:]` 送给 `future_pixel_values`，所以 **DINO 流实际只有 T=4 帧（偏移 3,7,11,15）**；当前帧只通过 `FutureEnc` 里的 `base_image` 进 VAE 那一路（`dinosiglip_vit.py` L202-206）。

## 候选 1（最高优先，near-free）：修 end-of-episode 塌缩 + 给 QFormer 加时间嵌入 —— 参照 Octo 的 pad_mask 范式

## 候选 2（最高信息价值，直接回答"5 帧这个 budget 对不对"）：Temporal Ratio + 现成的 horizon ablation 表

## 候选 3（对 83% 最有针对性的机制改造）：AHA-WAM 的时间不对称 + horizon-adaptive offset training

**arXiv**: 2606.09811 · https://arxiv.org/abs/2606.09811 · 提交 2026-06-08 · **Comments: `Project page: https://serene-sivy.github.io/aha-wam/`（venue: (none)）** · 代码 https://github.com/serene-sivy/AHA-WAM （**已 curl 200，title 确认为该论文的 repo**）

**为什么这篇是本 graft point 的核心参考**：它的摘要第一句就是用户 83% 诊断的独立复现（原文措辞）：

> "existing world-action models couple world prediction and action execution at the same temporal resolution, **forcing the world branch to model near-term frame variations that are redundant and weakly informative**"

**WoG 正是这个被批评的设计**：world 分支（QFormer 看 [0, Ta/4, Ta/2, 3Ta/4, Ta]）和 action 分支（16 步 chunk）**用完全相同的时间跨度**。AHA-WAM 的解法是**解耦**：

- 具体数字（我从 arXiv HTML 全文 §4.1 抓的）：**video 分支 h_v = 64，action 分支 h_a = 16**。注意 **h_a=16 与 WoG 的 Ta=16 完全相同** → 这是一个可以直接照搬的比例：**world 视界应该是 action 视界的 4 倍**。
- **Horizon-Adaptive Offset Training**（§3.3，我抓了原文）：不把 action chunk 对齐到 planner 起点，而是采样 `δ ~ U{0,1,...,h_a-1}`，把 action-chunk 网格在 planner 视界内平移 δ，loss 为 `L_a = E_δ[L_FM(A_τ^δ)]`。原文理由是防止 action head 过拟合到单一 planner-executor 相位。
- 配套：rolling FIFO K/V memory（最多 6 帧历史）+ OVCR（每 chunk 32 个 observation-guided routing query）。
- Ablation（Table 2, RoboTwin 2.0）：Fast-WAM 91.83 → Naive-Async 88.60 → +KV Memory 91.01 → +OVCR 91.47 → 完整 AHA-WAM **92.80**。实机 4 任务 78.33%（vs Fast-WAM 68.33%，π₀.₅ 76.67%），24.17 Hz，比 Fast-WAM 快 4.59×。

**怎么 graft 进 WoG**：

- **廉价变体（强烈推荐先做这个，几十行 + Stage I 重训）**：把 `future_obs_column_indices` 从 `[0, 3, 7, 11, 15]` 改成跨越 4Ta = 64 步的偏移，例如 `[0, 8, 24, 44, 63]`（对数/几何间距，近处密、远处疏）。**唯一改动就是 `traj_transforms.py` L49-54 那 5 行**，加上 `future_action_window_size` 要从 15 提到 63（`scripts/train.py:219`）。**注意这会同时改变 action chunk 的长度**——WoG 用 `actions[:, -self.Ta:]` 取后 16 个，所以要额外确认切片仍取到正确的 16 步（`vla/vla.py:176`），这是一个必须小心的地方。加上候选 1 的时间嵌入，总共 ~60 行。
- **offset training（~20 行，dataloader 内）**：训练时对 5 个偏移各加一个随机抖动 `δ ~ U{0, Ta/4}`，而不是恒定值。这**同时**是一个数据增强、**并且**逼迫时间嵌入学到平滑的连续表示（→ 支持后续候选 4 的可变偏移）。**注意：偏移一旦随机化，候选 1 的 `nn.Embedding` 就必须换成 Fourier/Time2Vec 型连续嵌入**（Time2Vec: arXiv 1907.05321，提交 2019-07-11，Comments: (none)，无官方代码）——否则无法泛化到未见偏移。
- **昂贵变体**：整套 dual-DiT + rolling memory + OVCR。这是重写架构，不建议。

**诊断预测（这是本报告最重要的机制论证）**：

用户的 83% 说的是「O^c 方差有 83% 可由 current-frame-only 编码线性重构」。设 O^c ≈ f(帧集合 S)，S = {I_t, I_{t+3}, I_{t+7}, I_{t+11}, I_{t+15}}。在 5 Hz 数据上 Ta=16 ≈ 3.2 秒，在 10 Hz 上 ≈ 1.6 秒；bridge/fractal 多数是缓慢的桌面抓放，**在 1.6-3.2 秒内场景外观的变化主要是机械臂自身的小幅位移，物体状态往往还没变**。所以 I_{t+15} 与 I_t 的 DINO 特征距离很小 → 帧集合的信息量 ≈ 单帧信息量 → **83% 是可以从"采样跨度太短"直接推出来的**。

把跨度拉到 4Ta = 64 步（6.4-12.8 秒）后：I_{t+63} 通常已经跨过了一个完整的子任务（抓取完成、物体已移位）→ 与 I_t 的特征距离大幅增加 → future-only 分量的信息量上升。**定量预期：83% 应显著下降**（我不能给可信的具体数字，这依赖数据集的时间尺度；但可以给一个**免训练的先验测量**：直接在数据上算 `||DINO(I_{t+k}) - DINO(I_t)||` 随 k 的曲线，以及"current-frame-only 探针 R²"随采样跨度 k 的曲线。**这个测量不需要训练任何东西，一个下午就能做完，应该在决定改不改跨度之前先做**。如果 R² 在 k=64 处仍然 >0.8，那这条路就不值得走，省下一次 Stage I 重训。）

**风险（必须诚实说明）**：candidate 2 的 Table 4 表面上与此矛盾（T=24 灾难性地差）。但如前所述那是**训练/推理不匹配**的 artifact（训练恒定 T=5），**不是**"长视界本质上有害"的证据。AHA-WAM 是**训练时就用 h_v=64** 的，两者不冲突。不过这仍然是一个真实的不确定性：WoG 是 5 帧的极小 budget，把它们摊到 64 步会让**近未来变得极稀疏**（最近的未来帧从 t+3 变到 t+8），可能损害精细接触阶段的精度 —— 这正是 candidate 2 观察到的"contact 阶段需要 anchor 到当前帧"。**折中方案：保持 5 帧但改成非均匀的 `[0, 4, 12, 32, 63]`**（近处保密度、远处加视界），这是我对这个 graft point 的**首选具体配置**。

## 候选 4（motion-adaptive 采样，dataloader-only，无需额外标注）：UVD 的 embedding phase-shift 检测

**arXiv**: 2310.08581 · https://arxiv.org/abs/2310.08581 · 提交 2023-10-12 · **Comments: (none)** · 代码 https://github.com/zcczhang/UVD （已 clone 验证）

**机制（我读了 `uvd/decomp/decomp.py` 的实际实现，L107-140）**：从轨迹**末尾往前**回溯。对当前 subgoal index，计算所有前序帧的 embedding 到该 subgoal 的 L2 距离 `||e_i - e_goal||`，用 `||e_0 - e_goal||` 归一化，`medfilt` 平滑，然后取 `np.gradient` 一阶（或二阶）导数；`|slope| >= derivative_threshold (1e-3)` 的区间就是"在变化"的段，连续 valid 区间被 `window_length=10` 的间隔切开，段的起止就是 subgoal。**纯 off-the-shelf 预训练视觉特征（可直接用 WoG 已有的 frozen DINOv2），零额外训练、零标注、无需 simulator。**

**怎么 graft**：这是**纯 dataloader 改动**，但有一个现实问题：UVD 需要**整条轨迹的 embedding**，而 WoG 的 RLDS pipeline 是流式的 per-trajectory transform。两条路：
- **(推荐) 离线预计算**：写一个一次性脚本，对每条 trajectory 跑 frozen DINOv2 + UVD，把 subgoal indices 存成一个 `{dataset, episode_id: [idx...]}` 的 sidecar 文件，dataloader 里查表。**优点**：DINOv2 只跑一遍（WoG 本来每步都在跑 DINOv2，这是净省算力）；**缺点**：需要一次全量 OXE 遍历（bridge+fractal 在多张 A100 上估计几小时到一天）。改动量：脚本 ~120 行 + `traj_transforms.py` ~30 行。
- **在线**：在 `chunk_act_obs` 之前加一个 traj-level transform，用轻量代理（比如像素差/光流能量，而不是 DINOv2）。~40 行，但精度差。

**新 loss**：无。**Stage I 必须重训**，Stage II 跟着重跑。

**诊断预测**：UVD 的 subgoal 定义就是"embedding 发生显著变化的点"，**这在定义上就是在最大化 future-frame 与 current-frame 的特征距离** → 直接攻击 83%。相比候选 3 的"盲目拉长跨度"，UVD 是"自适应地找到真正变了的地方"，在静态接近段会自动跳远、在接触密集段会自动加密 —— **这恰好是用户列出的缺陷 (1) 的教科书解法**。

**但有一个重要的不匹配需要指出**：UVD 找的是**任务级 subgoal**（一条轨迹通常只有 2-5 个），而 WoG 需要**每个 timestep t 都有 5 个条件帧**。所以不能直接用 UVD 的 subgoal 当条件帧，得改成"从 t 出发，取接下来的 K 个 UVD subgoal，不足则用等距填充"。这个适配逻辑本身需要仔细设计，是这个候选的主要工程风险。**另外：UVD subgoal 的间距是不规则的 → 时间嵌入必须是连续型（Fourier/Time2Vec），不能用 `nn.Embedding`。这是候选 1 与本候选的强耦合。**

**近亲（更简单，几乎零成本，值得作为 UVD 的对照基线）**：AWE（arXiv 2307.14326，提交 2023-07-26，**Comments: `The first two authors contributed equally`，venue: (none)**，代码 https://github.com/lucys0/awe 已 clone）。我读了 `waypoint_extraction/extract_waypoints.py` L13-72：贪心地反复把"线性插值重构误差最大的帧"加为 waypoint，直到总误差 < 阈值；**并且无条件把 gripper 开合状态发生翻转的帧加为 waypoint**（L27-31）。**后半句是本报告里最便宜的一个 idea**：WoG 的 action 是 7 维、第 7 维就是 gripper，`traj["action"]` 在 dataloader 里现成可得 —— **"把 gripper 状态翻转的帧强制作为条件帧之一"是十几行代码、零额外标注、零额外前向**。gripper 翻转恰好是抓取/释放这两个语义上最关键、视觉上变化最大的事件。KEMO（候选 5）的 ablation 独立证实了这类事件驱动选择优于均匀采样。

## 候选 5（事件驱动，有 ablation 直接支撑"事件驱动 > 均匀采样"）：KEMO / StaKe —— 从 proprioception + kinematics 免标注导出事件

**KEMO** · arXiv 2606.23589 · https://arxiv.org/abs/2606.23589 · 提交 2026-06-22 · **Comments: (none)** · **代码：摘要与 abs 页均未给出 URL → 未公开**

**机制**：结合 robot kinematics 与视觉过滤来检测事件，只保留与"任务相关状态变化"关联的 keyframe，编码为紧凑的**有时序的** memory token，用 cross-attention + gated residual fusion 融合。检测到的事件**还被用来给临界转换附近的训练样本加权**。

**直接可用的 ablation 结论（原文措辞）**："Ablations show that **event-driven keyframe selection outperforms uniform sampling and recent-frame retention**, while the proposed gated fusion and keyframe-aligned loss weighting provide complementary gains." 相对 π₀.₅ baseline：Task Success Rate +23.6%，Stage Completion Rate +34.1%（真实双臂，2-6 个子任务，830-2846 步）。**这是我找到的对"均匀采样是错的"最直接的实验证据**，虽然它的设定是 history/memory 而不是 future conditioning。

**StaKe** · arXiv 2606.26801 · https://arxiv.org/abs/2606.26801 · 提交 2026-06-25 · **Comments: (none)** · 项目页 https://hi-yuanxu.github.io/StaKe-Web/ （curl 200；但 `github.com/hi-yuanxu/StaKe` 返回 **404 → 代码未公开**）

**机制**：从 demonstration 的 **gripper state 自动导出**两个信号、**零人工标注**：(a) stage classifier（当前处于哪个操作阶段）；(b) keyframe predictor（下一个 gripper 转换点的目标 joint action）。两个轻量 auxiliary head，**不改 base VLA 架构、不改推理循环**。双臂仿真 +14%，Franka 实机 +56% 相对增益，**且长视界任务（更多 gripper 转换）增益更大**。

**怎么 graft**：
- 事件检测（免费）：`traj["action"][:, -1]` 就是 gripper。检测翻转 → 得到事件时刻。这与候选 4 的 AWE 启发式是同一个信号，**建议合并实现**。
- 事件驱动的条件帧选择：`traj_transforms.py` 里把 `[0,3,7,11,15]` 换成"当前帧 + 接下来 4 个 gripper 事件（不足则等距填充）"。~30 行，Stage I 重训。
- StaKe 式 auxiliary loss（可选，中等成本）：给 QFormer 加一个小 head 预测"下一个 gripper 转换的相对时间"，loss = MSE。这是一个**显式的 future-only 监督信号**，直接对抗"O^c 退化成 current-frame 编码"。~60 行 + Stage I 重训。**这是唯一一个我认为值得加新 loss 的候选。**
- KEMO 的 keyframe-aligned loss weighting：对靠近事件的样本加权。~15 行。

**诊断预测**：gripper 事件是**动作语义**的转换点，不一定是视觉变化最大的点（抓取瞬间视觉变化可能很小）。所以它攻击 83% 的力度可能不如 UVD，但它**几乎零成本、零风险**，而且 StaKe 的 auxiliary head 提供了一个**独立于 O^c 重构 loss 的 future-only 监督通路** —— 考虑到用户测到 Stage-II 的 obs_loss 只把 z 对 future-only residual 的预测力从 0.061 拉到 0.177（仍然很低），一个更直接的 future 监督信号是有道理的。

## 候选 6（可变视界/learnable timestep，作为长期方向；最贵）：SuSIE 的随机 subgoal_delta + VH-Diffuser 的可学习视界

**SuSIE** · arXiv 2310.10639 · https://arxiv.org/abs/2310.10639 · 提交 2023-10-16 · **Comments: `22 pages, 8 figures`（venue: (none)）** · 代码 https://github.com/kvablack/susie （已 clone，title 确认 "Code for subgoal synthesis via image editing"）

**机制（我读了 `susie/data/goal_relabeling.py` 的实现）**：subgoal **不是固定偏移，而是从一个区间里随机采样**：`subgoal_idx ~ U[curr + subgoal_delta[0], min(curr + subgoal_delta[1], goal)]`。`configs/base.py` L106/124 里 **bridge 和 something-something 都用 `subgoal_delta=(11, 14)`**；被注释掉的配置里 ego4d 用 `(30,60)`、CALVIN 用 `(20,21)`。

**这是一个直接可用的、经过实战检验的数字**：SuSIE 在 bridge 上选的 subgoal 偏移是 **11-14 步**，而 WoG 的最远未来帧偏移是 **15 步** —— **两者几乎一致**。这是一个支持"WoG 当前 budget 的最远端大致合理"的独立证据点，同时也说明 SuSIE 认为**单个** 11-14 步的 subgoal 就够了，不需要 5 帧。结合候选 3 的 h_v=4·h_a，一个合理的读法是：**近未来只需要 1-2 帧，剩下的 budget 应该花在更远的视界上** —— 这直接支持我在候选 3 里推荐的非均匀 `[0, 4, 12, 32, 63]`。

**随机化本身也是一个近乎免费的改动**：把 `[0,3,7,11,15]` 改成每次采样时加抖动（与候选 3 的 offset training 是同一件事，SuSIE 独立验证了它在 bridge 上有效）。~10 行。**但同样要求连续型时间嵌入。**

**VH-Diffuser** · arXiv 2509.11930 · https://arxiv.org/abs/2509.11930 · 提交 2025-09-15 · **Comments: (none)** · **代码：abs 页无 URL → 未公开**

**机制**：把 horizon 当**学习变量**而非超参。一个 Length Predictor 从 start-goal pair 预测 instance-specific 视界长度，再通过 **initial noise shaping** 控制生成轨迹长度，训练时在**随机裁剪的子轨迹**上训练 → 不需要改架构。

**GHIL-Glue** · arXiv 2410.20018 · https://arxiv.org/abs/2410.20018 · 提交 2024-10-26 · **Comments: (none)** · 代码 https://github.com/kyle-hatch-tri/ghil-glue （已 curl 200）—— 相关但正交：它做的是**过滤掉不带来 task progress 的 subgoal**。CALVIN 上跨多个 hierarchical model +25%。**这个"progress filter"思路可以直接用来筛掉 WoG 那些退化的重复帧**，是候选 1 的一个更聪明的版本（不只是 mask 掉，而是主动换一个有 progress 的帧）。

**怎么 graft**：SuSIE 式随机化 ~10 行（做）。VH-Diffuser 式的可学习视界需要给 WoG 加一个 length predictor + 让 QFormer 接受连续 offset 输入 → **~200+ 行、Stage I 重训、代码未公开**。**不建议现在做**；但如果候选 1+3 的实验显示"最优跨度强烈依赖任务/阶段"，这就是下一步。

**Hi-LeWM 的负面证据（值得引以为戒）** · arXiv 2607.12547 · https://arxiv.org/abs/2607.12547 · 提交 2026-07-14 · **Comments: `Accepted at WM@Booth 2026`** · 代码未见。它在 PushT/Cube 上扫 goal offset，发现"**hierarchy does not automatically improve performance**：短视界下最优配置是 one-step high-level horizon"，且瓶颈在 high-level subgoal 生成而非 low-level 执行。关键的一句：**用 true future latent subgoal 时 frozen low-level controller 执行得很好** —— 这对 WoG 是个好消息（Stage I 用的是**真实**未来帧，不是生成的），也是一个警告：**别急着把这个 graft point 做成层级化生成**。

## 我建议的执行顺序

**第 0 步（零训练，半天，应该先做）**：在现有数据上测两条曲线 —— (i) `||DINO(I_{t+k}) − DINO(I_t)||` vs k，k 扫到 64+；(ii)「current-frame-only 探针 R²」vs 采样跨度 k。**这直接判定候选 3/4 值不值得做，成本几乎为零。** 如果 R² 在 k=64 处仍 >0.8，跳过候选 3 和 4，省一次 Stage I 重训。

**第 1 步（~75 行，一次 Stage I 重训）**：候选 1a + 1b + 5a + 6a 打包。这四个都是 dataloader/QFormer 的小手术、互不冲突、且 1b 是后续一切的前置条件。重训后**重跑 83% 探针**。

**第 2 步（视第 0 步结果）**：候选 3a 的非均匀跨度，或候选 4 的 UVD。**这两个是互斥的替代方案**（一个是启发式非均匀，一个是学习/特征驱动非均匀），建议先做便宜的 3a 作为 4 的基线。
