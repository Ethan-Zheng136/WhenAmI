3.2 Observation-Guided Video-Context Routing Asynchronous execution reuses one planner video context for multiple action chunks, which amortizes video-DiT computation but creates a context-alignment problem: before the next planner refresh, the robot state and visual scene may have changed. Observation-Guided Video-Context Routing (OVCR) addresses this by using the latest visual observation to convert the shared planner context into a chunk-specific context. Instead of feeding dense visual tokens into the high-frequency action DiT, OVCR compresses them into a small set of routing queries that select and edit the relevant planner context before action denoising. For each action chunk at time t t , we split the aligned observation context into visual tokens X t v X^{v}_{t} and proprioceptive tokens X t s X^{s}_{t} . # GRAFT POINT 2：把 C(z) 变成 C(z,a) — 6 个可移植机制

**先说结论（排序理由）**：用户的诊断（O^c 因果效应 96–108% 来自 future-only 分量；真 z 下 O^c 影响低 36%；有效秩仅 18）指向同一件事——**O^c 现在携带的是"任务进度的平均未来"，这部分 z 已经能猜到；真正 z 猜不到的是"如果我执行这个 a，未来会怎样"**。所以让条件依赖 a 的价值不在"增加信息量"，而在**改变信息的类型**：从边缘未来 p(o_future|o_t, l) 变成条件未来 p(o_future|o_t, l, a)。这必然与 Stage-II（O^c 必须能从 z 单独预测）冲突，**这个冲突是整个方向的核心，我在每个候选的第 4 项都写明了它，并在最后给出三条化解路径**。

我已 clone WoG 源码（`/tmp/wog/WoG`）核对嫁接点，关键事实：
- `action_model/models.py:149` `DiTBlock.forward(x, per_token)`，`per_attn(norm3(x), per_token, per_token)` — Q=动作token，K/V=O^c，零初始化，24 层各一份。
- `vla/qformer.py:24` `QFormer.forward(visual_src, vae_latent)` — `visual_src` 就是 `encoder_hidden_states`，**要塞入动作只需把 x_t 投影后 concat 进 visual_src，5 行**。
- `vla/vla.py:172-181` `future_patch_features = self.qformer(...)` 然后 `.repeat(repeated_diffusion_steps,...)` — **QFormer 每个 batch 只跑一次然后按 t 复制**。一旦 O^c 依赖 x_t，这个 repeat 技巧失效，QFormer 必须进入 per-t 循环（这是主要的训练开销来源，务必先估算）。

## 候选 1（最推荐）：latent self-conditioning / self-conditioning —— C(z, x_t)，直接吃掉 rectified-flow 钩子

**1. 出处**
- **RIN (Recurrent Interface Networks)**，arXiv **2212.11972**，https://arxiv.org/abs/2212.11972 ，提交 2022-12-22（v2 2023-06-14），abs 页 Comments：**"ICML'23. Code at this https URL"**，代码 https://github.com/google-research/pix2seq （HTTP 200）。
- **Analog Bits / Bit Diffusion**，arXiv **2208.04202**，https://arxiv.org/abs/2208.04202 ，提交 2022-08-08（v2 2023-03-01），Comments：**"ICLR'23"**，代码同上 pix2seq。

**2. 机制（已从 ar5iv 全文核实）**
- RIN 把隐单元分成 interface X（与数据同维）和 **latents Z（m 个，与数据解耦）**，每个 block 做 Read（Z←X 交叉注意力）/ Compute（Z 自注意力）/ Write（X←Z 交叉注意力）。**"Stacking RIN blocks allows bottom-up and top-down feedback"** — 这就是双向。
- **latent self-conditioning**（原文公式）：`Z_t = Z_init + LayerNorm(Z_t' + MLP(Z_t'))`，其中 `Z_t'` 是**上一个扩散步算出的 latents**，LayerNorm 的 scale/bias **零初始化**，所以训练早期 `Z_t = Z_init`（与不加自条件完全等价）。**不需要 BPTT**。
- **训练期曝光偏差处理（这是本条最重要的部分，已核实原文与伪代码）**：Bit Diffusion 的原始配方是——`with some probability (e.g. 50%) 设 x̃_0 = 0`（退化为无自条件）；其余情况**先跑一次 `x̃_0 = f(x_t, 0, t)`，`stop_gradient`，再用它做第二次前向算 loss**。原文明确："we do not backpropagate through the estimated x̃_0 so the overall increase of training time is small (e.g., **less than 25%**)"。
- **RIN 的消融是硬证据**：Fig. 7(a) "Effect of the self-conditioning rate for training: **self-conditioning is crucial**; a rate of 0 is the special case of no self-conditioning… We use **0.9** for the best results"。即 90% 的 batch 用自条件、推理时始终用。**FID 与 rate 单调正相关。**
- 训练/推理仍有轻微不匹配（训练用同步 t 的估计，采样用上一步的估计）。Bit Diffusion 附录 G 给了两个补丁：momentum estimate（对历史估计做 EMA）与 **self-guidance**（每步跑两次前向，一次 x̃_0=0 一次带 x̃_0，加权组合，类似 CFG）。

**3. 怎么嫁接进 WoG（改动最小的一条）**
- QFormer 增加一路输入：`a_tok = self.a_proj(x_t)  # [B,16,7] -> [B,16,1024]`，`visual_src = cat([visual_src, vae_latent, a_tok], dim=1)`。**QFormer 本身是 BertModel + cross-attention，无需改结构**；`a_proj` 一个 `nn.Linear(7,1024)`（可零初始化输出以保证初始等价）。
- `per_attn` **不需要变双向**。这是本方案的关键卖点：O^c 已经通过 QFormer 读到了 x_t，动作→条件的信息流走 QFormer，条件→动作仍走原来单向 per_attn。**per_attn 一行不改。**
- 训练循环（`ActionModel.loss`）改成两次前向：
  ```
  with torch.no_grad():          # 概率 p≈0.9 走这支
      x1_hat = x_t + (1-t)*net(x_t, t, z, Oc(future, ZERO))   # 由速度反推 x1 估计
  Oc_sc = qformer(future, x1_hat.detach())
  v = net(x_t, t, z, Oc_sc); act_loss = ||v - u_t||^2
  ```
  另外 p≈0.1 的 batch 用 `a_tok=0`，保留"无动作条件"能力（这同时是 CFG 的无条件分支）。
- **新 loss：无**。只有一个额外前向。**Stage I 必须重训**（QFormer 输入变了）。
- 改动量估计：`qformer.py` +6 行，`vla.py` 里 qformer 调用移入 per-t 分支 +15 行，`action_model.py` loss +12 行。**总计 <50 行**。主要代价是 QFormer 从"每 batch 一次"变成"每 t 一次"，配合 `repeated_diffusion_steps` 会放大 —— 建议先把 `repeated_diffusion_steps` 调小或对 QFormer 做梯度检查点。
- **Stage II 影响：这是最温和的一条**。因为条件写成 `O^c = O^c_base(future) + Δ(future, x_t)`（Δ 零初始化）时，你可以**只把 O^c_base 蒸馏给 z（Stage II 原封不动），Δ 由一个 tiny action-aware head 在线产生**。见文末"化解路径 (c)"。

**4. 诊断预测**
- 用户测到 O^c 有效秩 18、top-8 方向复现 97.7% 的动作方向 —— 说明 512 个数里只有 ~8 个有用方向。**加动作依赖不需要扩容**：同样 16×32 的预算，但让这 8 个方向随 a 变化。预期"future-only 分量"的因果贡献会**下降**（因为一部分效应转移到 action-dependent 分量），这正是要看的信号。
- **是否带来 z 无法提供的新信息：会，且是唯一真正能做到的一类**。因为 Δ(future, x_t) 依赖 x_t，而 z 在 DiT 里是 token 0、与 t 无关，**结构上不可能编码 x_t 的函数**。这是"新信息"的严格论证，不是直觉。
- **是否让 Stage-II 蒸馏不可能**：只有 Δ 那部分不可能，base 部分照旧。用户已测到 Stage II 把 z 对 future-only residual 的可预测性从 0.061 抬到 0.177（约 3 倍但绝对值仍很低）—— 说明 Stage II 本来就没蒸馏成功多少，把不可蒸馏的部分**显式隔离出来**反而比现在混在一起更干净。

## 候选 2：非对称"干净动作→未来分支"单向路由（SelfWAM / GigaWorld-Policy）

**1. 出处**
- **SelfWAM: A Self-Grounded Unified World Action Model for Fast Robot Control**，arXiv **2608.00725**，https://arxiv.org/abs/2608.00725 ，提交 **2026-08-01**，Comments：**(none)**，项目页 https://selfwam.github.io/ 指向 https://github.com/SelfWAM/SelfWAM （HTTP 200，但**目录只有 docs / LICENSE / README.md —— 代码尚未真正放出，请视为"仓库已建、代码待发"**）。
- **GigaWorld-Policy: An Efficient Action-Centered World–Action Model**，arXiv **2603.17240**，https://arxiv.org/abs/2603.17240 ，提交 2026-03-18（v2 2026-03-21），Comments：**"Added references"**，代码 https://github.com/open-gigaai/giga-world-policy （HTTP 200）。
- （基线：**Fast-WAM**，arXiv **2603.16666**，2026-03-17，Comments (none) —— 就是"训练时联合建模、推理时砍掉未来分支"的那篇，WoG 的 Stage-II 是同一族思路。）

**2. 机制（已从 arXiv HTML 全文核实）**
- SelfWAM 在 Fast-WAM 的双流 MoT 上**只加一条单向路由**：把 demonstrated action chunk **复制一份保持干净（clean copy），赋予去噪时间步 t=0**，用同一个 action tokenizer/action blocks 编码，位置编码与对应的 noisy action token 对齐，**只暴露给 future-video queries**。原文："the noisy action-prediction queries attend only to the current observation, language instruction, proprioceptive state, and their own noisy action states; **they cannot access the clean-action copy or any future visual tokens**"。
- **曝光偏差处理 = 结构性回避，不是修正**。SelfWAM 明确说这是为了 "prevents target leakage while grounding predicted visual consequences"，并且 "leaving the fast action-only inference path unchanged"。部署时 clean-action 条件与 future-video 去噪**全部丢弃**。所以**它从来没有让动作条件在推理时起作用 —— 也就没有曝光偏差可言**。
- 一个非常有用的实测：附录 D 比较 clean path 与 noisy path 在 σ=0 时的逐层表示，**最大 NRMSE ≈ 1e-5、cosine distance ≈ 6e-11**，结论是 "The clean action representation can therefore be viewed as the **zero-noise endpoint of the action denoising path**"。**这直接证明"干净动作条件"和"完全去噪的动作条件"在表示层面是同一个东西**，为候选 1 的 x_t→a 插值设计提供了理论落脚点。
- **消融（重要的负面结果）**：Table 4，RoboTwin 2.0，FastWAM 91.84 → 只加 clean-action conditioning **90.80（掉 1.04 点）** → 再加 future self-mask 监督 92.62。**单独加"让未来依赖动作"是掉点的**，必须配合一个把未来目标聚焦到 action-relevant 区域的辅助目标（他们用 robot self-mask，由 RobotSeg/SAM2 离线生成）。延迟只 +0.97%。
- GigaWorld-Policy 是同一思路的**单栈共享权重版本**：所有 token 打成一条序列 `T=[T_o; T_s; T_a; T_f]`，blockwise causal mask —— (ii) `T_a` 只能看 `{T_s, T_o}`；(iii) `T_f` 可以看 `{T_s, T_o, T_a}`。**所有 token 共享同一套 QKV 投影**。视频 loss 条件里含 `T_a`（式 8），动作 loss 条件里不含 `T_f`（式 9）。⚠️ **未完全确认**：论文文字说"conditioned on … the **executed** action chunk"，但 `T_a` 在式 (5)(6) 里是流时间 s 下的 noisy token；两者是否同一份、s 是否跨模态共享，论文没写清楚。若确为 noisy，那 GigaWorld 实际上已经是"条件看到部分去噪的动作"，与候选 4 合流。

**3. 怎么嫁接进 WoG**
- 这是**唯一不动 per_attn 就能实现 C(z,a) 且完全不破坏 Stage II 的做法**，因为动作条件只作用在"生成未来"这一侧，而 WoG 的 O^c 恰好是"未来的压缩"。
- 具体：Stage I 现在 `obs_loss` 被硬置零（`vla.py:183`），**把它打开**，让 QFormer 的输出（或一个新的小 future-decoder）去重建 future DINOv2 patch / Wan VAE latent，并且**这个重建的条件里加入干净动作 a_gt**（走 QFormer 的 `encoder_hidden_states` 或一个新的 cross-attn）。同时保持 `per_attn` 里动作 token 看到的 O^c 是**不含 a 的那一支**（或含 a 但走 stop-gradient）。
- **新 loss**：一个 future-reconstruction loss（SelfWAM 用 flow-matching MSE + mask BCE/Dice/IoU）。SelfWAM 的消融说明**光有 RGB 重建会掉点，需要 action-relevant 目标**。在 WoG 上不需要 SAM2 分割：更省的替代是**用 O^c 的 "future-only 残差"作为重建目标**（用户已经有这个量），或用 DINOv2 patch 的帧间差分（只保留变化区域）—— 这条**不需要额外标注、不需要仿真器**，符合硬约束。
- **Stage I 必须重训**。改动量：`qformer.py` +10 行（第二路 a 输入 + 一个 decoder head），`vla.py` +30 行（打开 obs_loss、构造未来重建目标）。**~50–80 行**。
- **Stage II 完全不受影响** —— 这是本条最大优势。O^c 仍然只是 future 的函数（a 只在辅助重建 loss 里出现），`oformer` 从 `obs_ins` 预测 O^c_hat 的设定原封不动。

**4. 诊断预测**
- 与用户诊断最契合的一条推理：如果 O^c 的因果效应 96–108% 来自 future-only 分量，而 future-only 分量 83% 能被"current-frame-only 版本"线性重建，那**当前的未来编码几乎没在编码"运动"**。SelfWAM 的定向扰动实验（Fig. 4/S2：action-unconditioned baseline 在动作插值 α∈[0,1] 下预测的未来"几乎不变"，SelfWAM 则单调跟随）**正是这个病的独立复现**。
- **不带来 z 无法提供的新信息（这是本条的诚实缺点）**：因为部署时 a 不参与，O^c 仍是 future 的确定性函数。它带来的是**表示质量提升**（O^c 从"平均未来"变成"该动作下的未来"），预期效应是有效秩上升、future-only 分量在因果分解里占比下降、`per_attn` 的零初始化门控学到更大的权重。但 **Stage-II 的"z 猜 O^c"难度会上升**（因为 O^c 变得更依赖具体动作，而 z 不含动作）—— SelfWAM 的 -1.04 点掉分很可能就是这个张力的表现。
- **不会让 Stage II 不可能**，但会让它更难。这是"温和但天花板低"的一条。

## 候选 3：把条件和动作一起联合去噪（LAWA / Being-H0.7 对照）

**1. 出处**
- **Latent Action as Intention Enables Efficient Future Imagination for World Action Models (LAWA)**，arXiv **2608.24882**，https://arxiv.org/abs/2608.24882 ，提交 2026-08-25（v2 2026-09-01），Comments：**(none)**。原文 "Code and models **will be released**" —— **代码尚未公开**。
- 对照：**Being-H0.7: A Latent World-Action Model from Egocentric Videos**，arXiv **2605.00078**，https://arxiv.org/abs/2605.00078 ，提交 2026-04-30，Comments (none)。**它就是 WoG Stage-II 的同构方案**（deployable prior branch 从当前上下文推 latent queries，training-only posterior branch 用未来观测的 embedding 替换 queries，两支在 latent 空间对齐）—— 可以当作 WoG 的直接竞品/对照来引用。

**2. 机制（已从 arXiv HTML 全文核实）**
- LAWA 的核心：**不要把未来蒸馏成"z 的函数"，而是让它在推理时和动作一起被去噪**。三个 expert（video / latent-action / action）通过 joint attention 耦合，structured mask：current-obs token 看不到未来；**latent action token 只看当前观测 + latent action 序列；action token 看当前观测 + latent action 序列 + action 序列**。
- **推理时丢掉 video 分支，只联合去噪 latent intention 和可执行动作**："the action expert conditions on the **evolving continuous latent state**"。也就是每个流步，条件都在更新，且条件的更新看不到 GT 未来 —— **这是真正的 C(z, ·) 在线共推断，最接近用户自己的研究方向**。
- 训练：三个分支**独立采样 flow time τ_m 和独立噪声**，`L = λ_vid·L_vid + λ_lat·L_lat + λ_act·L_act`。tokenizer 先在 action-free video 上预训练（L1 + LPIPS + mask BCE/Dice/IoU），然后冻结，用 noise-substitution quantization 避免 codebook loss。
- **曝光偏差处理**："The same visibility mask is maintained **across training and inference**" —— 训练和推理的可见性完全一致（都看不到未来观测），因此**没有 train/test mismatch**。代价是 latent intention 在训练时的监督目标来自冻结 tokenizer 编码的 GT 未来，所以 latent 分支自身仍是 teacher-forced；但因为它和动作**同步去噪、共享噪声级别分布**，动作 expert 在训练时看到的就是"部分去噪的 latent"，不是干净 GT。
- **实证**：RoboCasa few-shot 65.6% / full 80.8%，比 matched Fast-WAM 基线 **+9.6 / +4.5 点**；比 matched Joint-WAM 性能持平但延迟 **-42.9%**。**并且论文明确报告了对用户重要的负面发现**："our matched implementations show **lower generalization for Fast-WAM** than for future-aware alternatives, especially with scarce robot demonstrations and in OOD scenarios" —— 即 WoG 那种"推理时砍掉未来分支"的做法在 OOD 下确实吃亏（Faster-WAM 2608.04404 独立复现：LIBERO-Plus 上 Fast-WAM 49.14% → 保留推理期未来条件 73.57%）。

**3. 怎么嫁接进 WoG（改动最大，但最贴合用户主线）**
- **这是"废掉 Stage II、改成联合去噪"的方案**。`oformer` 整个删掉。新增一个 tiny "condition expert"（可以直接复用 QFormer 的 6 层 1024，或缩到 2–3 层）在推理时存活，与 DiT 一起迭代：
  ```
  for t in flow_steps:
      Oc_t = cond_expert(z, Oc_{t-1}, x_t, t)      # 16x32，自身也做 flow matching
      v    = DiT(x_t, t, z, per_token=Oc_t)        # per_attn 不变
      x_{t+1} = x_t + v*dt
  ```
- `per_attn` **仍可保持单向**（动作 Q、O^c K/V），因为反向信息流由 cond_expert 显式承担。若想更彻底，可以把 `DiTBlock` 的 `attn`（现在只在动作序列内自注意力）换成对 `cat([x, Oc_t])` 的 joint self-attention + block mask —— 那才是真双向，但要改 24 个 block，且零初始化保护会失效（`per_attn` 的 ControlNet 式零初始化是 WoG 稳定性的关键，别轻易破坏）。
- **新 loss**：`L_cond`（cond_expert 的 flow-matching velocity MSE，target 是 Stage-I 冻结 QFormer 给出的 O^c）。这实际上是把 WoG 的 `0.3 * obs_loss`（cosine）**换成一个 flow-matching loss**，且监督对象从"z 单点回归 O^c"变成"从噪声去噪到 O^c"。
- **Stage I 不必重训**（冻结的 QFormer 继续当 target 提供者），**Stage II 完全重写**。改动量：新增 `cond_expert`（~80 行），`vla.py` 训练路径 +40 行，`action_model.inference` 重写（+30 行）。**~150–200 行 + Stage II 全量重训**。
- **对 Stage-II 张力的处理：直接消解**。Stage II 的约束"O^c 必须能从 z 单独预测"被替换成"O^c 必须能从 z 出发、在与动作共同迭代中被去噪出来"。**后者严格更弱**（前者是后者在 1 步、无 x_t 输入时的特例），所以**不存在"不可能"的问题**。

**4. 诊断预测**
- 这是**唯一能同时解决"future-only 冗余"和"z 已含 O^c 大部分信息"两个诊断的方案**。因为：(a) O^c 变成 x_t 的函数 → z 结构上无法替代；(b) O^c 每步都在变 → 不再是一个秩 18 的静态向量，而是一条轨迹，表达能力上限大幅提高。
- 风险预测：`per_attn` 是零初始化的，如果 cond_expert 早期输出噪声，DiT 会学会**忽略** O^c（门控保持接近零），退化成纯 z 条件策略。**必须做的诊断**：训练中监控 `per_attn.out_proj.weight` 的范数增长曲线，和 O^c 的因果效应（用户已有的 ablation 探针）。如果 per_attn 权重不长，方案失败，回退到候选 1。
- 另一个风险：16 个 query 高度冗余（单 token 探针 R²=0.62，全 16 个仅 0.645）。在联合去噪设定下这个冗余可能**恶化**（更多自由度、更弱监督）。建议先把 query 数从 16 降到 4–8 做对照，验证冗余是不是被"目标太容易"所致。

## 候选 4：噪声级别解耦 —— 条件应该在动作的哪个去噪深度被读出（Diffusion Forcing / DiT4DiT / SANTS）

**1. 出处**
- **Diffusion Forcing: Next-token Prediction Meets Full-Sequence Diffusion**，arXiv **2407.01392**，https://arxiv.org/abs/2407.01392 ，提交 2024-07-01（v4 2024-12-10），Comments：**"Project website: this https URL"（无会议名）**，代码 https://github.com/buoyancy99/diffusion-forcing （HTTP 200）。
- **DiT4DiT: Jointly Modeling Video Dynamics and Actions for Generalizable Robot Control**，arXiv **2603.10448**，https://arxiv.org/abs/2603.10448 ，提交 2026-03-11（v2 2026-03-22），Comments：项目页链接，代码 https://github.com/Mondo-Robotics/DiT4DiT （HTTP 200，含 `DiT4DiT/ decoupled_wbc/ deployment/ examples/` —— **真代码**）。
- **SANTS: A State-Adaptive Scheduler for World Action Models**，arXiv **2605.27947**，https://arxiv.org/abs/2605.27947 ，提交 2026-05-27（v3 2026-08-26），Comments："13 pages, 5 figures, 8 tables. Project page"，代码 https://github.com/Advanced-Robotics-Lab/SANTS-code （HTTP 200）。

**2. 机制（已核实）**
- **Diffusion Forcing**：每个 token 独立随机噪声级别，"noising tokens is a form of **partial masking** — zero noise means a token is unmasked, and complete noise fully masks out a token"。用一个共享的 next-or-next-few-token 模型去噪任意噪声级别组合。这给出**"条件可以在动作处于任意去噪程度时被读出"的训练范式**，且原文明确对比了 teacher forcing / full-sequence diffusion 的失败模式。附带能力：Monte Carlo Guidance、causal uncertainty（远未来保持更高噪声）。D4RL maze 上 167.1 vs Diffuser 149.4（multi-task avg 146.2）。
- **DiT4DiT 的 tri-timestep 设计是本条最实用的工程结论**（已核实原文）：三个时间步完全解耦 —— 视频 `τ_v ~ U[0,1]`（学全去噪轨迹）；动作 `τ_a = 1-σ, σ~Beta(α,β)`（偏向关键控制阶段 —— **和 WoG 的 `sample_t_beta(1.5, 1.0)` 完全同源**）；而**条件特征在一个固定的确定性时间步 τ_f 处抽取**。原文理由："the feature extraction process requires **deterministic and consistent** representations across iterations to ensure the downstream action module receives a **stable** input signal… **By fixing this value, we stabilize the latent representations**"。而且它不用重建的未来帧，直接用**视频去噪过程的中间 hidden state** 当条件。收益：LIBERO 98.6%、RoboCasa-GR1 50.8%，样本效率 >10×、收敛快 7×。
- **SANTS 补上了 τ_f 该取多少的答案（且是反直觉的）**："**the best action condition is not necessarily the fully denoised video**. Controlled denoising-depth scans show that video refinement can reduce action error up to a **state-dependent** point, after which the gain may **saturate or even reverse**"。他们训了一个轻量 scheduler 预测 cumulative stopping hazard + relative noise-progression ratio，**用冻结动作分支产出的最终动作质量作为 path-level reward 做后训练**（不是用中间视频保真度）。RoboTwin 2.0 94.4%、7 个真机任务 73.1%，延迟 -81.7% / -79.0%。

**3. 怎么嫁接进 WoG**
- WoG 目前 **O^c 与 t 完全无关**（`vla.py` 里 qformer 跑一次然后 repeat）。最小改动：**给 QFormer 加一个 timestep embedding 输入**，让 `O^c = QFormer(future, vae, temb(t))`。这甚至还不是 C(z,a)，只是 C(z,t)，但是**一个必做的 ablation**：它能把"条件随流步变化"这个因素和"条件依赖动作内容"这个因素分离开。约 10 行。
- 完整版：`O^c = QFormer(future_at_noise_τ_f, a_hat_at_τ_a)`，其中 τ_a 就是当前流步 t，τ_f 固定（按 DiT4DiT 的建议）。因为 WoG 的"未来"是 DINOv2 patch + Wan VAE latent，**没有视频去噪过程可供抽 hidden state**，所以 τ_f 这一维在 WoG 里退化 —— 但 SANTS 的结论仍适用于**动作侧**：应该扫一遍"在哪些 t 让 O^c 看到 x_t"，而不是所有 t 都看。WoG 用 `t ~ Beta(1.5,1.0)`（偏向 t→1，即接近干净动作），**这恰好是 x_t 信息量最大的区间，是个天然优势**。
- **新 loss：无**（如果只做 t/噪声解耦）。若加 SANTS 式 scheduler，需要一个 path-level reward 后训练阶段（REINFORCE/DPO 风格），这在 A100 上可做但不需要仿真器——用离线数据的 action MSE 当 reward 就行。
- **Stage I 需重训**（QFormer 输入变了）。改动量：解耦版 ~20 行；SANTS 式 scheduler ~150 行 + 一个后训练阶段。
- **Stage II 影响**：如果 O^c 依赖 t，那 `oformer` 要么也变成 t 依赖（Stage II 成本 ×N_steps），要么只蒸馏某个代表性 t 的 O^c（信息损失）。**这是本条的主要成本**。折中：只在 t > 0.5（Beta 分布的主要质量区）让 O^c 依赖 x_t，t < 0.5 时 O^c 退化为纯 future 函数，Stage II 只蒸馏后者。

**4. 诊断预测**
- SANTS 的"denoising-depth scan 存在最优点、过了会反转"直接预测：**WoG 在不同 t 注入 O^c 的收益应该是非单调的**。用户已有的因果效应探针可以立刻做这个扫描（把 `per_attn` 在 t 的子区间内置零），成本极低，**建议作为第一个实验**。它能在写任何新代码之前告出"条件该不该随 t 变"。
- 关于"新信息"：C(z,t) 本身**不带来新信息**（t 是已知的、DiT 通过 `t_embedder` 已经看到了）。真正带新信息的是 C(z, x_t)，即候选 1。所以本条的定位是**候选 1 的必要 ablation 与超参指南，不是独立方案**。我把它单列是因为 DiT4DiT 的"τ_f 必须固定才稳定"和 SANTS 的"最优深度是 state-dependent 且会反转"这两个结论，会直接决定候选 1 和候选 3 的成败，跳过会踩坑。

## 候选 5：不动 Stage I —— 把 C(z,a) 做成推理期的打分器/引导项（Feedback World Model / τ0-WM / GPC）

**1. 出处**
- **Feedback World Model Enables Precise Guidance of Diffusion Policy**，arXiv **2605.15705**，https://arxiv.org/abs/2605.15705 ，提交 2026-05-15，Comments：**"21 pages, 9 figures"（无会议名）**，**未找到公开代码**。
- **τ₀-WM: A Unified Video-Action World Model for Robotic Manipulation**，arXiv **2606.01027**，https://arxiv.org/abs/2606.01027 ，提交 2026-05-31（v2 2026-08-23），Comments：项目页，代码 https://github.com/sii-research/tau-0-wm （HTTP 200）。
- **Generative Predictive Control (GPC)**，arXiv **2502.00622**，https://arxiv.org/abs/2502.00622 ，提交 2025-02-02（v4 2026-03-11），Comments：**"Acceptance to IEEE Robotics and Automation Letters. Website: this https URL"**，**未找到公开代码仓库**（我尝试的候选 URL 均 404）。

**2. 机制（已核实）**
- **Feedback WM 里有一个对用户诊断直接可用的量化工具**（已核实公式 14–16）：用**反事实方差**估计每个 latent 维度的"动作可控性"：
  `w_j = (1/M) Σ_i Var_{a~A_demo}( [f_θ(z_i, a)]_j )`，M=200 个状态、每状态 32 个动作样本；归一化后 `w_j^(β) = 1 + β(w̄_j - 1)`，用它加权 guidance 的 MSE。理由："latent representations often **entangle controllable factors** … with **weakly controllable factors**, such as background appearance and lighting"。效果：OOD 下 WM 预测误差降 76.4%，Robomimic+LIBERO-Plus 平均成功率 0.40 → **0.52**（Std. Guid. 0.43、Rollout Guid. 0.45）。另一半是 feedback state 的在线校正（latent-space observer，有收敛性证明）。
- **τ0-WM 的两级 test-time compute**（已核实第 VI 节）：(a) **Re-denoising Consistency Score (RCS)** —— 对每个候选动作 chunk 随机采 K 个流步重新加噪、用同一个 action vector field 评估平均去噪误差，取负作为分数，选 argmax。**完全不需要世界模型，只用策略自己，开销极小**。(b) 当 `S_RCS < γ` 时才调用 action-conditioned video simulator，rollout 候选动作、预测 dense task-progress reward，`J = max_q r̂_{t+q}`，选最高的 rollout，然后**把选中的 rollout latent 转成额外的 future condition 再灌回策略做第二次查询**（"low-quality action rectification"）。⚠️ 这个 rectification 步骤**就是一次显式的 C(z,a) 反馈闭环**，且是 WoG 架构下几乎零改动可实现的（O^c 的接口本来就是"未来的压缩表示"）。
- **GPC**：冻结 diffusion policy + action-conditioned world model（在专家演示 **和随机探索 rollout** 上训练），对策略提出的候选做 look-ahead 排序与精化，**不重训策略**。
- **曝光偏差**：这一类**天然没有曝光偏差**，因为世界模型在推理时接收的就是策略自己的输出。代价转移成了另一个问题：**世界模型对 OOD 动作的预测不可靠**。Feedback WM 的整篇文章就是在解这个（在线反馈校正）；GPC 的解法是训练数据里**掺入随机探索 rollout**（覆盖非专家动作）。这是本类方案的真实风险点。

**3. 怎么嫁接进 WoG（改动最小的"零风险探路"方案）**
- **RCS 版本：Stage I / Stage II 都不动，一行不改模型**。部署时用现有 `ActionModel.inference` 采 N 个候选，对每个候选随机采 K 个 t 重新加噪、跑 `net(x_t, t, z)` 算速度残差，选最小。**纯推理端脚本，~40 行**。这不是 C(z,a)，但它是**验证"动作候选之间确实存在质量差异、且策略自己能分辨"的最便宜实验**。如果 RCS 在 WoG 上没有增益，说明候选质量差异不是瓶颈，候选 5 整条线可以放弃。
- **C(z,a) 打分器版本**：训一个小模型 `g(O^c_hat_from_z, a) → scalar`（或 → O^c 的一个修正量），在 Stage-I 数据上用"该 a 是否是 GT"做对比学习。推理时把 `∇_a g` 加进流步：`x_{t+1} = x_t + (v + λ·∇_{x_t} g) dt`。**Stage I 不重训，Stage II 不重训**，只加一个外挂模块（~120 行 + 一个小训练脚本）。
- **反事实方差探针**（Feedback WM 公式 14）**应该立刻做，无论选哪个候选**：把 WoG 的 QFormer 当 `f_θ`，但它现在不接受 a —— 所以退而求其次：对 512 维 O^c 的每一维，测它在固定 z、不同 GT 动作对应的不同 future 下的方差，vs 在固定 future、不同 z 下的方差。**这能直接量化"O^c 的哪些维度是 action-relevant 的"，并且和用户已有的"future-only 分量 96–108%"结论交叉验证**。~50 行分析脚本。

**4. 诊断预测**
- 用户测到"真 z 下 O^c 因果影响低 36%"。这在打分器框架下有个具体含义：**z 已经把"平均最优动作"确定得很好，边际信息在于"排除次优动作"**。这正是 verifier / RCS 擅长的事 —— **打分器只需要区分好坏，不需要生成新信息**。所以候选 5 的预期收益模式与候选 1/3 不同：它不提高单次采样质量，而是提高 best-of-N。
- **是否带来 z 无法提供的新信息：不带来，也不需要**。打分器不改变 O^c，它改变的是采样分布。**因此完全不触碰 Stage-II 张力** —— 这是本条唯一但很重要的优势。
- **是否让 Stage II 不可能：不会，零影响。**
- 主要风险（要明说）：Feedback WM 与 GPC 的增益都建立在"世界模型对候选动作的预测足够准"上，而 WoG 的 O^c 只有 512 个数、有效秩 18。**用一个秩 18 的表示去区分 N 个候选动作的未来，很可能分辨率不够**。建议先用反事实方差探针测 O^c 对动作扰动的响应幅度（对应 CoCo 的 ARC 指标，见下）；如果响应接近零，候选 5 直接失效。
