### 0.1 源码校正：WoG 的 DiT **完全没有 adaLN**——它是纯 in-context DiT

我 clone 了 `github.com/Selen-Suyue/WoG` 读了 `action_model/models.py`。除 CONTEXT.md 已给的事实外，有一条关键补充：

没有任何 `modulate()`、没有回归 shift/scale/gate、`FinalLayer` 也没有 adaLN。**结论：24 层 DiT-L 里，timestep t 和 z 唯一的注入方式就是 `c = t.unsqueeze(1) + z` 这一个 token（L303-305），且它在 17 个 token 的序列里占 1 个，最后被 `x[:, 1:]` 丢掉。** t 的条件化强度极弱——这本身可能是一个独立于 z/O^c 之争的缺陷。

这条事实把候选 (a)/(e) 的价值大幅提高，也让「给 t 单独加 adaLN-Zero」成为最低风险的改动（见候选 4）。

### 0.2 Stage-II 存活筛选（本 graft point 最硬的判据）

Stage II：`use_per_attn=False` + `obs_dropout_prob=1`，per_attn 在权重层面不存在。所以**任何只改 per_attn 通路的机制，其收益只能通过下面这条 3 跳衰减链到达部署**：

> per_attn 更好 → Stage-I 里 qformer 得到更好的梯度 → O^c 质量更高 → Stage-II 里 O^c.detach() 作为 obs_loss 蒸馏目标更好 → oformer（**训练完即丢弃**）→ 梯度经 obs_ins 回到 VLM。

## 候选 1（首推）：FLARE —— 把 O^c 从「条件」变成 DiT **内部激活的对齐目标**

**1. 出处**
- arXiv **2505.15659**，https://arxiv.org/abs/2505.15659，提交 **2025-05-21**
- abs 页 Comments：`Project Webpage / Blogpost: https://research.nvidia.com/labs/gear/flare`（**无会议名**，即 venue = (none)）
- 代码：**未找到独立公开 repo**。GitHub 代码搜索 `FLARE robot world modeling` 返回 0；`NVIDIA/Isaac-GR00T`(HTTP 200) 是其 backbone 但我未确认其中含 FLARE 实现。**代码可用性 = UNVERIFIED / 大概率无**。这是它唯一的硬伤。

**2. 精确机制**（已从 PDF 正文核实）
在 DiT 输入序列里加 M 个 **learnable future token**（与 state token、noised action token 并列，参与同一个 self-attention）。在**中间层 L** 切出这 M 个 token 的激活，过一个 MLP，与未来观测 o_{t+H} 的冻结 embedding 做**余弦对齐**：

> `L_align = −E_τ[cos(f_θ(φ_t, A^τ_t, q_t), g(φ_{t+H}))]`，总损失 `L = L_fm + λ·L_align`，**λ=0.2 最佳**。

关键消融（已核实数值）：
- 目标 embedding 选择：**No FLARE loss 43.9% → SigLIP2 49.6% → SigLIP2 avg-pool 50.9% → action-aware embedding 55.0%**
- 层位置：8 层 DiT 里用**第 6 层**最好；"applying the alignment objective too early—e.g., at layer 4—leads to a notable drop"
- EMA 目标：baseline 60.1% → ρ=0.995 时 66.4%（所有 EMA 变体都超 baseline）

**3. 如何嫁接进 WoG（具体）**
- **改哪条通路**：`per_attn` 通路**整条删除**（K/V 注入换成序列内 token + loss）。z 的 token-0 通路**不动**。
- 新模块：`DiT.__init__` 里加 `self.future_tokens = [REDACTED], hidden_size))`（16 个，对齐 O^c 的 16 query）+ 一个 `nn.Linear(1024, 32)` 投影头。`forward` 里 `x = torch.cat((c, x, future_tok), dim=1)`，`positional_embedding` 从 `Ta+1` 扩到 `Ta+1+16`。在第 **L≈16/24** 层（按 FLARE 的 6/8 比例）切出 future token 激活。
- **新 loss（需要）**：`obs_loss` 从「oformer 预测 O^c」改成「**DiT 第 16 层的 future-token 激活对齐 O^c.detach()**」。注意 WoG 现有 obs_loss 已经是 `1 − cos(normalize·normalize)`，**形式与 FLARE 完全一致，只是对齐点从 DiT 外部（oformer）搬到 DiT 内部**。λ 沿用 0.3 或试 0.2。
- **Stage-II / 部署存活性：★★★★★ 完全存活。** 这是它排第一的理由。future token 是 action 序列的一部分、是权重里的 `nn.Parameter`，不是可删的旁路；对齐损失塑造的是 **24 层 DiT 主干自己的表征**。部署时 O^c 不参与——正确，因为它从来只是训练目标，不是输入。**这条改动把 WoG 现有那条「训练完就扔掉 oformer」的浪费直接修掉了。**
- 改动量：`models.py` ~25 行、`vla.py` ~15 行、删 `oformer` ~10 行。**Stage I 与 Stage II 都要重训**（或者：可以直接合并成单阶段，这是附带收益）。

**4. 诊断预测**
用户测到「Stage-II 把 z 对 future-only 残差的可预测性从 0.061 提到 0.177（~3x）」——这说明 WoG 的 obs_loss 方向是对的，但**只作用在 VLM 上，DiT 主干完全没被这个目标塑造**。FLARE 正是把同一个目标施加到 DiT 内部。对 36% 竞争：**O^c 一旦不再是条件，就不存在与 z 争夺条件带宽的问题**——竞争被结构性消除（而非缓解）。同时「top-8 主方向复现 97.7% 动作方向」意味着 O^c 是个低秩、易预测的目标，作为对齐目标非常合适（不需要模型去拟合 512 维噪声）。

## 候选 2（并列首推，机制解释力最强）：DIAL —— 把 z 与 O^c 融成**单一流** + 结构性瓶颈

**1. 出处**
- arXiv **2603.29844**（v2, 2026-04-28），https://arxiv.org/abs/2603.29844，首次提交 **2026-03-31**
- Comments：`Project page: https://xpeng-robotics.github.io/dial`（venue = (none)，preprint）
- 代码：项目页指向 **https://github.com/xpeng-robotics/DIAL**（HTTP 200，已确认存在）。作者含 HKU + XPENG Robotics（与 WoG 的 HKU 血缘接近）。

**2. 精确机制**（已核实正文）
- System-2（VLM）：追加 N 个 learnable query，输出经 MLP 得到 **latent foresight x_t**，用 MSE 对齐**同一个冻结 ViT** 编码的 o_{t+H}：`L_world = ‖x_t − Enc_ViT(o_{t+H})‖²`。
- System-1：用**同一个冻结 ViT** 编码当前观测；**一个 4 层 self-attention 模块把 `Enc_ViT(o_t)` 和 `x_t` 融合成单一条件**，再作为 **16 层 DiT 的 cross-attention 条件**。DiT 于是成为一个 **latent inverse dynamics model**：动作必须由「当前状态 ↔ 预测未来」之差导出。
- 两阶段：Stage 1 解耦预热（System-1 用 **ground-truth** 未来特征训练，System-2 独立学 L_world）；Stage 2 换成 System-2 合成的 x_t，端到端可微，动作梯度回传进 VLM。

**这篇的消融几乎是在直接测量 WoG 的病**（数值已核实，few-shot 100 traj/task，RoboCasa GR1）：

| 接口设计 | 成功率 | 与 WoG 的对应 |
|---|---|---|
| GR00T-Qwen2.5 冻结 | 21.8% | 无世界建模 |
| + full FT | 30.6% | |
| **+SEER**（future token 拼到策略输入） | **49.6%** | ≈ WoG 的 in-context 松耦合 |
| **+SEER-EV**（再给 System-1 一条直接视觉通路） | **47.2%** | **≈ WoG：z 已经看过当前帧** |
| **+FLARE**（只作辅助 loss，执行时不强制用） | **51.9%** | |
| **DIAL**（结构性瓶颈） | **58.3%** | |

原文两句话是对 36% 这个数字最贴合的机制解释：
> "When the intent signal is not structurally enforced, the policy tends to **bypass the high-level intent and instead exploit superficial shortcuts**, since there is no architectural constraint requiring the intent to be faithfully translated into action."
> "Notably, adding an extra visual pathway in SEER-EV even **degrades** performance (49.6%→47.2%), indicating that **unconstrained access to raw features exacerbates the tendency to ignore cognitive foresight**."

**3. 如何嫁接**
- **改哪条通路**：**两条都改，合并成一条。** 删掉 `per_attn`；`c = t + z` 这个 token-0 也不再承担 z 的注入职责。新增一个 4 层 self-attention `fusion`，输入 `[z_proj ; O^c]`（或部署时 `[z_proj ; O^c_hat]`），输出作为**每层 cross-attention 的唯一 K/V**。
- 新 loss：`L_world`（MSE 或余弦，把 z 侧 query 对齐未来 DINOv2 特征）——**WoG 的 Stage-II obs_loss 已经是这个东西，只是 oformer 被丢弃**。DIAL 的做法是把它变成常驻结构。
- **Stage-II / 部署存活性：★★★★★ 按构造存活。** 部署时 O^c_hat 由 VLM query 直接产出、fusion 模块常驻权重、DiT 的 cross-attn 常驻。**这等于把 WoG 的两阶段割裂彻底修掉：oformer 不再是弃件，而是 System-2 的输出头。**
- 改动量：**最大的一个**。`models.py` 需要给 DiTBlock 加回 cross-attn（~40 行）+ fusion 模块（~40 行）+ `vla.py` 改造 ~50 行。**两阶段全部重训**，且需要 DIAL 的「解耦预热→端到端」调度（否则 posterior collapse，原文明确点出）。
- 一个**必须注意的偏离**：DIAL 强调 System-1 与 System-2 **共享同一个冻结 ViT**，并消融证明换成 DINOv2 会从 58.3% 掉到 47.2%（"geometric richness alone is insufficient"）。WoG 恰好用的是**冻结 DINOv2 + Wan VAE**，与 VLM 的视觉塔不同源。**这是嫁接时的一个明确风险点**，DIAL 的数据说这个不一致会吃掉一半增益。

**4. 诊断预测**
最能把竞争变成组合的机制。理由：36% 的成因不是梯度冲突，而是**条件冗余 + O^c 通路可被绕过**（zero-init 的 per_attn 没有任何压力去长大，因为 z 单独就能把 act_loss 压下去）。DIAL 通过让动作**必须**由 (当前, 未来) 之差导出，消除了绕过路径。它同时解释了 83% 当前帧可重建这一条为什么是坏消息（SEER-EV 的教训）——但 DIAL 的解法不是删掉当前帧通路，而是把当前帧和未来放进**同一个特征空间做差分**，这样重叠的 83% 会在差分中自然抵消，剩下的正是 future-only 分量（用户测到 O^c 因果效应 96–108% 来自该分量）。**这是唯一一个能把「83% 冗余」从缺陷转成算术优势的机制。**

| Mutual | 92.50 | 91.80 | **92.15** ✅ |

**但这些设定的真实含义必须校正——这一点很重要，我从源码 docstring 读到的定义与直觉不同：**

```
- mutual            video sees action; action sees all of video
- action_sees_video video does not see action; action sees all of video
- video_sees_action video sees action; action sees only the FIRST video frame
- isolated          video does not see action; action sees only the FIRST video frame (FastWAM-style)
```
代码 `fill_cross_modal_va_blocks()` 证实：
```python
else:  # VIDEO_SEES_ACTION, ISOLATED: first frame only
    mask[a_start:a_end, v_start:v_end] = False
    mask[a_start:a_end, v_start : v_start+ff] = True
```
**所以 "Isolated" ≠ 动作流看不到任何视觉信息，而是「动作流只能看当前帧（第一帧 = clean conditioning frame），看不到未来帧」。** 于是 **87.41 → 92.39 这 ~5 个点，精确地就是「未来帧可见性」的价值，在当前帧可见性完全受控的条件下测得。** 这与用户的两条诊断（O^c 因果效应 96–108% 来自 future-only 分量；83% 可由当前帧重建）是**同一件事的两个测法**——OpenWAM 说这个 future-only 增量在他们的设定里值 5 个点，WoG 目前只兑现了其中被 36% 压制后的一部分。

另外补上你没提到但同样有用的架构消融（Table 1，同 benchmark）：

| 架构 | Clean | Random. | **Avg** |
|---|---|---|---|

→ **joint self-attention 比 joint cross-attention 高 4.11 点**（92.36 vs 88.25）。WoG 用的正是 cross-attention。
→ **MoE 是全表最差**，比 vanilla 还低——对候选「MoE 路由条件」是**反证**。
→ Tri-System 里 VLM 理解流的接法（对应 WoG 的 z）：源码 `build_cross_modal_attention_mask` 的 `n_readonly_tail`：
```python
mask[:tail_start, tail_start:] = True   # video + action 都能看 tail
mask[tail_start:, tail_start:] = True   # tail 只看自己，永不看 video/action
```

**即 z 应当是一个「所有人都可读、自己不读别人」的只读尾巴。**

预训练后偏好反转（Fig 11，已核实）：from-scratch 时 Action-Sees-Video 略优（Mutual −0.24），**预训练后 Mutual 反超（+0.16 / +0.70 / +0.72）**。推理期调度消融：**同步去噪最优（93.0），所有异步 schedule 都不如它**。

**3. 如何嫁接**
- **改哪条通路**：`per_attn` 从 cross-attn 改成**把 O^c 的 16 个 token 直接拼进 action 序列**，用一个 visibility mask 控制可见性（action 看 O^c，O^c 不看 action = `action_sees_video`）。z 改为**只读尾巴 token**（所有 action token 都能 attend 到它，它只 attend 自己），而不是现在这个「加到 t 上、参与全序列双向注意力、最后被丢掉」的 token-0。
- 新 loss：**不需要**。这是纯注意力掩码 + 序列布局改动。
- **Stage-II / 部署存活性：★★☆☆☆ 部分存活，且要小心。** z 改成只读尾巴这一半**完全存活**（z 在部署时存在）；O^c 拼进序列这一半在 Stage II **不存在**（obs_dropout=1）。但比现状好的一点：因为不再有独立的 `per_attn` 权重，Stage I / Stage II 的**权重拓扑一致**（不再是 350 vs 204 tensors），Stage II 只需把 O^c 的 token 位置换成 O^c_hat 或直接截断序列，**不再需要删除整个模块**。这本身就消除了一个大的 train/deploy 不匹配。
- 改动量：`models.py` 里 DiTBlock 的 `Attention` 需要支持 attn_mask（timm 的 `Attention` 不支持，需换成手写或 `F.scaled_dot_product_attention`，~30 行）+ 掩码构造 ~40 行（可直接照抄 OpenWAM 的 `mask_modes.py`，Apache-2.0）。**Stage I 重训；Stage II 需重训但拓扑更干净。**

**4. 诊断预测**
这是 4-6 个候选里**唯一有直接同类可比数字**的（world-action model、真机器人成功率、控制良好的消融）。对 36% 的预测：把 z 变成只读尾巴会**降低** z 的强势——现在 z 加到 t 上并参与双向注意力，它既是条件又能被动作 token 反向影响；改成只读后 z 只能被读取。这在结构上更接近「组合」而非「竞争」。**但我要明确标注：OpenWAM 没有测量条件间竞争，也没有 WoG 那种 causal-influence 指标，所以「只读尾巴能缓解 36%」是我的推断，不是论文结论。**

## 候选 4（性价比最高的小改动）：DiT 原始消融 —— 给 t（以及 z）加 adaLN-Zero

**1. 出处**
- arXiv **2212.09748**（v2, 2023-03-02），https://arxiv.org/abs/2212.09748，提交 **2022-12-19**
- Comments：`Code, project page and videos available at https://www.wpeebles.com/DiT`（abs 页无会议名；实际为 ICCV 2023，但按你的规则记 venue = (none)）
- 代码：https://github.com/facebookresearch/DiT（HTTP 200）

**2. 你要的数字：已从论文附录 Table 4 逐字核实**（全部 DiT-XL/2，400K steps，**无 CFG**，FID-50K）

| Block 设计 | Gflops | Params(M) | **FID-50K ↓** |
|---|---|---|---|
| **in-context** | 119.37 | 449 | **35.24** ← WoG 的 z 通路 |
| **cross-attention** | 137.62 | 598 | **26.14** ← WoG 的 O^c 通路 |
| adaLN | 118.56 | 600 | **25.21** |
| **adaLN-Zero** | 118.64 | 675 | **19.47** |

正文原话：`"At 400K training iterations, the FID achieved with the adaLN-Zero model is nearly half that of the in-context model"`；`"Cross-attention adds the most Gflops... roughly a 15% overhead"`；`"adaLN... is the only conditioning mechanism that is restricted to apply the same function to all tokens"`。

**WoG 的两条通路恰好是这张表里最差的两名（35.24 和 26.14），而 adaLN-Zero 是最好的（19.47）。**

**3. 如何嫁接**（这是候选 (a) 和 (e) 的证据基础，但我要拆成三个不同存活性的子改动）

- **4a. 给 t 单独加 adaLN-Zero（不涉及 z、不涉及 O^c）** —— **强烈推荐先做这个**
  依据 §0.1：WoG 现在 t 只通过一个会被丢弃的 token 注入。加 `self.adaLN_modulation = nn.Sequential(nn.SiLU(), nn.Linear(D, 6*D))`（zero-init 输出）+ `modulate()`。
  **Stage-II 存活性：★★★★★ 完全存活**（t 在部署时当然存在）。
  改动量：**~25 行**，`models.py` 一个文件。Stage I + II 都要重训（权重拓扑变了）。
  这是**唯一一个既有硬数据支持、又完全存活、又只有几十行、且与 z/O^c 之争正交**的改动。作为其它实验的新 baseline 也更公平。

- **4b. 把 z 也回归进 adaLN（`c = t + z` → 一起送进 modulation MLP）** —— 这就是 DiT 论文的原始 adaLN 语义
  **Stage-II 存活性：★★★★★ 完全存活。** z 是 1 个 token（4096→1024），压成 shift/scale/gate 没有信息损失顾虑（RDT 反对 adaLN 的理由是「条件太长、变长」——不适用于 1-token 的 z）。
  改动量：**~5 行**（在 4a 基础上把 z 加进去）。

- **4c. 把 O^c 走 adaLN-Zero（候选 a 的原始形式）** —— **不推荐**
  两个理由。(i) O^c 是 [B,16,32] 的 16 个 token，adaLN 必须先池化成 1 个向量才能回归 shift/scale——而用户诊断「单 token probe R²=0.62，全 16 token 只有 0.645」说明池化损失很小，所以技术上可行；(ii) **但 Stage-II 存活性 = ★☆☆☆☆**，这条通路在 Stage II 整个不存在，只经 §0.2 那条 3 跳衰减链起作用。**按你的筛选原则，这个候选应当被否掉。**

- **4d. 给 z 也加每层 cross-attention（候选 e，apples-to-apples 对照）**
  **Stage-II 存活性：★★★★☆ 存活**（z 存在）。但 DiT 的数据说 cross-attention（26.14）显著不如 adaLN-Zero（19.47），且贵 15% Gflops。**作为「公平对照实验」它有价值（能干净地回答「36% 是不是纯粹由注入方式不对称造成的」），但作为最终方案不如 4b。** 建议作为诊断实验而非改进方案。

**4. 诊断预测**
DiT 的数字**不能直接回答 36%**——它是单条件（class label）实验，没有条件竞争。它能回答的是：「z 现在的注入方式（in-context）在同等算力下是四种里最差的，差距接近 2 倍 FID」。对 36% 的解释：如果 z 的注入本身就很弱，那 O^c 在真 z 下影响低 36% 反而更奇怪——说明 z 尽管注入方式差，仍然携带了足以让 DiT 忽略 O^c 的信息。**这条推理支持「问题在于 O^c 的边际信息太少」而非「z 的通路太强」，因此进一步佐证候选 1/2 的方向优于候选 3/4。**

## 候选 5：RDT-1B 的 Alternating Condition Injection（ACI）—— 直接为「两个条件互相压制」而设计

**1. 出处**
- arXiv **2410.07864**（v2, 2025-03-01），https://arxiv.org/abs/2410.07864，提交 **2024-10-10**
- Comments：`10 pages, conference`（**abs 页 Comments 里没有会议名**；PDF 页眉写 "Published as a conference paper at ICLR 2025"）
- 代码：https://github.com/thu-ml/RoboticsDiffusionTransformer（HTTP 200）

**2. 精确机制**（正文原话，已核实）
> "These informative conditions are challenging to compress into a single token, **making the original adaptive layer norm approach unsuitable**. Therefore, we employ cross-attention to accommodate conditions of varying lengths... Besides, we further analyze that, **given that image tokens are usually much more than text tokens, simultaneous injection of both modalities tends to overshadow text-related information, thus impairing the capability of the instruction following**... To mitigate this issue, we **strategically alternate between injecting image and text tokens in successive layers' cross-attention rather than injecting both in every layer.**"

这是文献里对「两个条件在 per-layer cross-attention 中相互压制」最直接的表述，且给出的解法极简：**奇数层注入条件 A，偶数层注入条件 B。**

**⚠️ 证据强度警告（UNVERIFIED）**：ACI 的定量证据是 Fig 4(b) 的柱状图。我从 PDF 提取时该图的坐标轴标签是 `/uni0000005a/uni00000012/uni00000052...` 形式的 glyph 编码，**无法读出具体成功率数字**。表 2 的消融只覆盖 regress/small/scratch 三个变体，**不含 w/o ACI**。所以「ACI 值多少个点」我**无法核实**——只能核实机制陈述和它确实是论文的三大改动之一。

**3. 如何嫁接**
- **改哪条通路**：两条都改。z 不再走 token-0，而是和 O^c 一样走 cross-attention，然后**交替**：第 0,2,4,…22 层注入 z，第 1,3,5,…23 层注入 O^c。
- 新 loss：不需要。
- **Stage-II / 部署存活性：★★☆☆☆ 且有一个具体危害。** Stage II 里 O^c 消失，那 12 个「偶数层」变成**完全无条件层**——z 的注入层数从 24 直接腰斩到 12。**这几乎肯定会让部署性能变差。** LLaMA-Adapter 的插入层数消融（见候选 6）正好量化了这个风险方向：10 层 55.95 → 20 层 73.36 → 30 层 83.85。层数减半的代价可能很大。
- **改进变体（我的建议，无直接文献支持，标为推测）**：**跨机制交替而非跨层交替**——z 走每层 adaLN-Zero（候选 4b），O^c 走每层 cross-attention。两者不争夺同一个注入槽位（一个改 LayerNorm 的仿射参数，一个加残差项），Stage II 删掉 O^c 后 z 的 24 层 adaLN 完好无损。**这个组合同时满足「消除竞争」和「Stage-II 完全存活」，是我认为的最佳低风险方案。**
- 改动量：原版 ACI ~15 行（一个 `if layer_idx % 2` 判断）；改进变体 ~30 行。

**4. 诊断预测**
ACI 的因果故事（token 多的条件压制 token 少的条件）在 WoG 里**方向相反**：O^c 是 16 token 走 24 层 cross-attn，z 是 1 token 走 token-0——按 RDT 的逻辑应该是 **O^c 压制 z**，但用户测到的是 z 压制 O^c（真 z 下 O^c 影响低 36%）。**这个不一致本身是有信息量的**：说明 WoG 的压制不是由「注入带宽/token 数」驱动的，而是由**信息内容冗余**驱动的（z 经 VLM 已看过当前帧，而 O^c 83% 可由当前帧重建）。**这削弱了 ACI 类「重新分配注入槽位」方案对 WoG 的适用性，并再次把答案指向候选 1/2。**

## 候选 6：条件不对称/一方被忽略的诊断与修法合集（含正交/互补惩罚 = 候选 c，与 zero-init 的批评）

这一组我按「支持 / 反对」分开列，因为它们主要提供的是**判据和警告**，而不是单个可嫁接模块。

### 6A. Uni-ControlNet —— 「弱条件在联合训练中学不动」的直接实测
- arXiv **2305.16322**（v3, 2023-10-29），https://arxiv.org/abs/2305.16322，提交 **2023-05-25**
- Comments：`Camera Ready, Code is available at https://github.com/ShihaoZhaoZSH/Uni-ControlNet`（venue = (none)；实为 NeurIPS 2023）；代码 HTTP 200
- **核心结论（正文原话，已核实）**：`"the reason why Training-S1 gets poor controllability on the global condition is that the global control adapter does not learn as much as local adapter even equally treated during joint fine-tuning. One possible explanation is that the local conditions often contain more rich guidance information than global conditions, leading the model to pay less attention to the global condition."`
- 数值（Table 4，FID↓）：Training-S1（**从头联合训练**）21.21/27.20/20.78/23.22/27.83/25.01/24.99/**28.51** vs Training-S2（先分开训再联合）18.80/…/**24.84** vs 默认（**只分开训、推理时直接合并、不联合微调**）18.24/…/24.86。**从头联合训练在所有 8 列上都最差；而「分开训 + 不联合微调」和「分开训 + 再联合微调」几乎相同。**
- **对 WoG 的判据**：WoG Stage I 是把 z 和 O^c **从头联合训练**——Uni-ControlNet 说这是三种策略里最差的。**可嫁接的最小改动：Stage I 分成两个子阶段（先只用 O^c 训 per_attn + qformer，z dropout=1；再放开 z）**，约 10 行（改 `class_dropout_prob` 的调度）。Stage-II 存活性 ★★★☆☆（它改善的是 qformer/O^c 的质量，即 §0.2 那条链的第一跳，仍有衰减）。
- 另一个可用件：其 **FDN**（Feature Denormalization，SPADE 式）`FDN_r(Z_r, c_l) = norm(Z_r)·(1 + conv_γ(zero(h_r(c_l)))) + conv_β(zero(h_r(c_l)))`——这是候选 (a) 的一个空间感知版本，且它的消融证明**多尺度注入优于只在输入层注入**（Injection-S1 25.89 vs Injection-S2 22.22 vs FDN 18.24 on Canny）。

### 6B. ControlNeXt —— 对 **zero-init 本身**的直接批评（针对 WoG 的 4 个 zero-init per_attn 权重）
- arXiv **2408.06070**（v3, 2025-03-08），https://arxiv.org/abs/2408.06070，提交 **2024-08-12**
- Comments：`controllable generation`（venue = (none)）；代码 https://github.com/dvlab-research/ControlNeXt（HTTP 200）
- **原话**：`"zero initialization also slows convergence and increases training challenges by preventing the modules from receiving accurate gradients at the start. This results in a phenomenon known as 'sudden convergence' in controllable generation, where the model doesn't gradually learn the conditions but abruptly starts to follow them after an extended training."`
- 替代方案 **Cross Normalization**：用主干特征 x_m 的 channel-wise 均值/方差去归一化控制特征 x_c，再相加（不用 zero-init）。
- 另一条与 WoG 高度相关：`"we found that directly adding the controls to the inputs results in training collapse, possibly due to the confusion and overlap between the controls and denoising features. Thus, we inject the controls after the first block"` —— **「控制信号与去噪特征混淆重叠导致崩溃」正是 WoG 那个 `c = t + z` 加到 token-0 的操作类型。**
- **对 WoG 的意义**：WoG 的 per_attn 是 4 个权重全 zero-init，**而且只在 Stage I 存在**。如果它遭遇 sudden convergence（一段时间几乎不学、之后突然开始学），而 Stage I 的训练长度不足以走过那个拐点，**那 per_attn 可能根本就没学起来——这将是 36% 的一个平凡解释，且是可直接检验的**：查 Stage-I checkpoint 里 `per_attn.out_proj.weight` 的范数是否仍接近 0。**这是我建议优先做的一个 5 分钟诊断。**
- Stage-II 存活性 ★☆☆☆☆（只改 per_attn）。**所以它的价值是诊断价值，不是嫁接价值。**

### 6C. 正交/互补惩罚（候选 c）—— 有支持，但我建议不做
- **最贴切的支持**：**InstructMoLE**，arXiv **2512.21788**（v3, 2026-05-03），https://arxiv.org/abs/2512.21788，提交 **2025-12-25**，Comments = **(none)**，代码 https://github.com/yanq095/InstructMoLE（HTTP 200，ByteDance + Rutgers）。其 **output-space orthogonality loss** 专治「expert collapse / 功能冗余」，`L_total = L_flow + λ_aux·L_aux + λ_ortho·L_ortho`。消融（Table 4，已核实）：**加 ortho loss 单独贡献 Canny F1 38.12→40.22（CLIP 路由）、38.92→41.51（Zglobal 路由）；Pose F1 36.74→36.79 / 37.77→40.97。** 增益真实但不大（1–3 点）。
- 损失形式的经典出处：**Barlow Twins** arXiv 2103.03230（2021-03-04，Comments: `13 pages, 6 figures, to appear at ICML 2021`）、**VICReg** arXiv 2105.04906（2021-05-11，Comments: `Accepted at ICLR 2022`）——交叉相关矩阵的非对角元惩罚，是「让两个条件流互补而非冗余」最标准的 10 行实现。
- 嫁接：在 Stage I 加 `L_ortho = ‖corr(z_proj, pool(O^c))_offdiag‖²`，~15 行。
- **Stage-II 存活性 ★★★☆☆**（它塑造 `z_embedder.linear` 和 qformer，这些部分存活）。
- **但我建议不做，理由基于用户自己的诊断**：「O^c 的 top-8 主方向复现 97.7% 的动作方向（cos 0.977）」——O^c 里**有用的部分恰恰就是与动作（因而也与 z 所编码的意图）高度对齐的那部分**。强制 z 与 O^c 正交，会把 O^c 推向剩下的 10 个有效维度，那里要么是 83% 的当前帧冗余、要么是噪声。**正交惩罚在这里有相当大概率是有害的，它会把「冗余但有用」误当成「需要消除的冗余」。** 真正需要保留的是**互补性（complementarity）而非正交性**——而互补性没有简单的可微惩罚。**这是我对候选 (c) 的明确否定判断。**
